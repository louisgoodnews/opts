## 🎯 Objective

A player can change every key the game reacts to, in the settings, and nothing in the interface tells them a key that is no longer true. A binding can be put back to its default one by one, per group or all at once.

Today (2026-10-20): the 25 vehicle actions (battery, lights, doors ...) are rebindable (`controls.vehicle.*`, [vehicle_keys](../../simulation/vehicle-keys.md)); every other key is fixed in code (about 330 `KeyCode::` reads in 34 files: driving, gears, cameras, overlays, maps, quick save, theme, developer panel, pause). The hints print the default keys as text (`hud-hint-controls`: "W/S Throttle and brake - ... - F1 Help"; the Help overlay's table `help/controls.rs`; button labels such as "Pause [Esc]"). Only a single binding has a *Reset* button.

## 📋 Scope

- **One registry of actions** (`opts_bevy::action_keys`): id, group, default chord, label; the input systems ask it (`just_pressed(action)`) instead of naming a `KeyCode`. The registry holds the current chord of every action, filled from the settings `controls.<group>.<id>`.
- **Conflicts across everything**: a chord that another action (vehicle or built-in) uses, or a key the interface itself uses and that cannot move (Esc as *cancel*, Tab and Enter in dialogs), is refused with the name of the action in the way; unbinding is allowed.
- **Hints from the binding**: texts that name a key carry a placeholder (`{ $help }`) filled from the registry each frame the binding changes; the Help overlay, the HUD hint line, the tooltips and the footer read it. A test fails for a message that spells a default key.
- **Reset**: the row's *Reset* (exists), a group (*Reset keys of this group*) and *Reset all key bindings* in the *Controls* page, and `settings.reset` for a key (exists); one command for the group and all (`settings.reset_group {prefix}`).
- **Axes and multi-key actions** (throttle W/S, steering ←/→, the gear keys, camera 1 to 5 and 0): one action each with a *positive* and a *negative* chord, or a list of chords; the analog inputs of a gamepad or wheel stay M-0035's.
- **Persistence and profiles**: bindings are plain settings (the database and `settings.toml`), never part of a map profile; `settings.export` and `import` carry them.

**Out of scope:** gamepad and steering wheel mapping (needs [M-0035](M-0035.md)'s device work), key combinations of more than Ctrl and Shift, per-vehicle key sets, the keys of the `keyboard.cfg` IBIS/blind/cash-desk bindings (they stay the installation's; the vehicle's own hot-spot controls are the way to operate them).

## ✅ Acceptance Criteria

1. In the settings, every key the player presses in a drive can be rebound; a key that cannot (a fixed interface key) is listed as fixed with its reason.
2. Rebinding changes what the game reacts to at once, and every hint, tooltip and the Help overlay show the new key.
3. *Reset* restores one binding, a group or all bindings to the defaults; after a reset the database holds no custom binding.
4. A conflict is refused with the name of the action that has the key.
5. `./scripts/local-ci.sh` passes.

## ⚠️ Risks & Mitigations

| Risk | Mitigation |
| :--- | :--- |
| 330 key reads in 34 files: a half migration leaves some keys fixed | A test over the source files lists every remaining `KeyCode::` read; the fixed ones are named with a reason |
| Layout: keys are physical, a hint shows the physical key's name | Show the name of the key as in the settings (`KeyChord::to_text`); a layout-aware label (the character the key makes) is a later refinement ❓ |
| Modifier matching changes behaviour (Shift+F7 vs F7) | Exact matching with the actions split where OPTS already used modifiers (mini map) |
