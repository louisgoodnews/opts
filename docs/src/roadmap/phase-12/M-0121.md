## 🎯 Objective

Rain makes vehicles, buildings and street furniture look wet (darker, smoother, glossier) and snow settles on scenery that has a snow state, with the same single weather driver that already wets the ground and roads. OMSI does this with per-texture flags and variants, not with a separate wetness or snow map type (see [Corrections to the brief](README.md#corrections-to-the-brief)).

**What exists already (build on it, do not duplicate), verified in the code 2026-10-18:**

- Ground and roads: `crates/opts-game/src/in_game/weather/surfaces.rs` writes the weather's wetness, puddles and snow cover into the ground shader's `wet` uniform (`crates/opts-bevy/src/ground_material.rs`) and into the road materials, from `[groundwet]`, `[snow]` and `[snowOnRoad]` (`crates/opts-omsi/src/formats/weather.rs`). The single wetness driver is the `Wetness` resource of `crates/opts-bevy/src/reflections.rs`.
- Texture flags are **documented but not parsed**: `[moisture]` (7,040 textures), `[puddles]` (4,266) and `[surface]` in the texture `.cfg` ([texture-cfg.md](../../formats/text/texture-cfg.md)). No code reads `moisture` per texture.
- Snow in scenery: `[visible]` with the variable `snow_visible` (and `winterhalbjahr`/`sommerhalbjahr`; [sco.md](../../formats/text/sco.md), [scenery-scripts.md](../../formats/text/scenery-scripts.md) 18/24 uses) plus `WinterSnow`/`WinterSnowfall` texture sub-folders ([textures.md](../../formats/textures.md) lookup rules). How the existing `[visible]` handling sources the value of `snow_visible` from the session is part of the audit.
- Rain on glass, dirt and condensation overlays are [M-0120](M-0120.md).

---

## 🔍 Scope

**In scope:** (a) parse `[moisture]`/`[puddles]` per texture and make exactly those materials wet with the global wetness (vehicle bodies, scenery objects, splines); (b) feed `snow_visible`/season variables from the session environment and select the `WinterSnow` texture variants where they exist; (c) vehicles: wet paint and tyres through the same wetness; (d) a setting; (e) tests and docs.

**Out of scope:** puddle geometry on objects, dripping or running water, accumulation over time (a rule-based ramp is allowed, a simulation is not), snow depth affecting vehicle physics (grip stays with [M-0117](../phase-11/M-0117.md)), a new snow particle system (precipitation already exists).

## 📦 Deliverables & Tasks

- [ ] Texture `.cfg` parser keys `[moisture]`, `[puddles]` exposed on the texture asset, with corpus counts in a test fixture (small synthetic `.cfg`, no OMSI file committed).
- [ ] Material wetness: textures with `[moisture]` take the `Wetness` factor (darker albedo, lower roughness, more reflection) via the shared function of the reflections path; textures without the flag stay dry. Vehicles use the same rule.
- [ ] Snow state: a session environment value for `snow_visible`/season delivered to scenery `[visible]` evaluation; `WinterSnow` variant lookup on map or weather (precedence documented in the notes).
- [ ] Ramp: wetness and snow cover follow the weather over a documented time (no instant flip), reusing the ground path's ramp.
- [ ] Setting *Wet and snowy surfaces* (Off / Ground only / All), consistent with `WeatherEffects.wet_ground`.
- [ ] Docs: `weather.md` section on objects and vehicles, `texture-cfg.md` (OPTS handling), `sco.md`; unknowns (what `[puddles]` means on non-ground objects) marked ❓.

## ✅ Acceptance Criteria

1. A texture with `[moisture]` renders darker and with lower roughness at wetness 1 than at 0; the same texture without the flag is pixel-identical (unit test on the material function plus one A/B pair).
2. A Berlin-Spandau scene in the "rain" preset shows wet vehicle bodies and facades with `[moisture]` textures; the visual A/B harness mean luma of the body crop drops by a documented margin versus dry.
3. With the session set to winter/snow, an object whose `[visible] snow_visible` mesh exists shows it; with summer it does not; objects with a `WinterSnow` texture variant use it (test with a synthetic object and the lookup function).
4. Wetness and snow cover change over time without a one-frame pop (max per-frame change tested).
5. Setting Off or Ground only leaves objects and vehicles dry; the render matches today's (MAE below 0.5 %).
6. Cost: at most 0.3 ms per frame on the RTX 3060 12 GB at 1920x1080 on the reference scene (no per-frame material rebuilds; changes only when the factor changes).

All gates pass (`cargo fmt`, `cargo clippy -D warnings`, `cargo test --workspace --all-features`, `./scripts/local-ci.sh`); no unsafe code; no OMSI asset committed.

## ⚠️ Risks & Mitigations

| Risk | Mitigation |
| :--- | :--- |
| Mutating thousands of materials each frame | Drive wetness through one shared uniform or a change-threshold update; never per-material per-frame writes |
| `[moisture]` semantics on non-ground objects are not documented | Record the observed meaning, keep the flag handling in one function, default to dry when unsure |
| Snow variants differ per map author and folder | Documented lookup precedence; no variant means no snow, never a missing texture |
| Overlaps with M-0117 (grip) | M-0121 only draws; the wetness value is read-only for physics |
