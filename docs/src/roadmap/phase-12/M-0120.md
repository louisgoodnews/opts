## 🎯 Objective

Dirt, rain on glass and condensation show on vehicles and scenery the way the scripts drive them, and light maps (`[matl_lightmap]`, `[matl_nightmap]`) light up at night and in lit rooms exactly as the model files say. Both are **material features**, not new file types (see [Corrections to the brief](README.md#corrections-to-the-brief)).

**What exists already (build on it, do not duplicate), verified in the code 2026-10-18:**

- Parsing is done: `[alphascale]`, `[matl_change]`, `[matl_lightmap]`, `[matl_nightmap]`, `[nightmapmode]` in `crates/opts-omsi/src/formats/vehicles/model/parse.rs` and `ast.rs` and in `crates/opts-omsi/src/formats/scenery/sco.rs` (tests in `crates/opts-omsi/tests/model_parse.rs`, `scenery_runtime_parse.rs`). Format background: [sco.md](../../formats/text/sco.md), [script sets](../../formats/text/vehicles/script-sets.md) (`dirt.osc`).
- Light maps run in part: vehicle light maps become emissive scaled by their script variable (`crates/opts-bevy/src/vehicle_lights.rs`, `LightMapBinding`, [M-0045](../phase-4/M-0045.md)); scenery has `SceneryLightMap` (`crates/opts-bevy/src/scenery_runtime/effects.rs`, `spawn.rs`). The tile's baked terrain light map (`[LightMapMapping]`) is a separate feature of the [lighting system](../../architecture/lighting-system.md).
- Alpha scaling by `Envir_Brightness` runs live for glass (`crates/opts-bevy/src/scenery_runtime/alpha.rs`; tests `crates/opts-bevy/tests/sd83_glass.rs`).
- **Not done:** overlays whose variable starts with `rain_window_`, `dirt_` or `precip_` are deliberately never built (`is_static_overlay` in `crates/opts-bevy/src/model.rs`, "always 0"); the script host exposes `dirt_norm` as an output with no consumer (`crates/opts-sim/src/script/inputs.rs`). [sco.md](../../formats/text/sco.md) therefore still states that OPTS hides these overlays (`Q-SCO-AS1`).
- `[nightmapmode]` 0-4 is parsed; whether all five modes are applied is not confirmed and is the first thing the audit settles.

---

## 🔍 Scope

**In scope:** (a) an audit of overlay and light-map behaviour against corpus counts and the five `[nightmapmode]` values; (b) building the dirt, rain-on-glass and condensation overlays as alpha materials driven each frame by the vehicle's script variables (`Dirt_Norm`, `Dirt_Wiped`, `Rain_Window_*_Wetness`, `Beschlag_*`), with the wipers' wiped variant; (c) completing `[matl_change]` and `[matl_lightmap]`/`[matl_nightmap]` behaviour for vehicles and scenery per mode; (d) a setting for overlay quality; (e) docs correction.

**Out of scope:** new map or file types, the *simulation* of where rain falls or dirt accumulates beyond what the stock scripts compute, weather-dependent surface wetness and snow ([M-0121](M-0121.md)), baked terrain light maps, global illumination.

## 📦 Deliverables & Tasks

### Audit
- [ ] Table in this file's Notes: per overlay variable class (dirt, rain window, condensation, precipitation mirror) and per `[nightmapmode]` value 0-4, the corpus count, the current OPTS behaviour and the target. Unknown semantics marked ❓ and settled by a rendering experiment, not guessed.

### Overlays
- [ ] Replace the blanket `is_static_overlay` rule: build overlay parts, bind them to the live script variable (vehicles: the script VM; scenery: the object's own script), hide a part only while its alpha product is 0.
- [ ] Wire the existing weather state to the stock scripts' inputs so rain and `Dirt_*` evolve without OPTS inventing values (the scripts compute dirt and wiping; the host supplies precipitation and the `veh_wash` trigger).
- [ ] Setting *Window and body overlays* (Off / Simple / Full) with the live-switch pattern of the lighting settings; default Full on the reference hardware, Off removes the entities entirely.

### Light maps
- [ ] Apply `[nightmapmode]` 0-4 in vehicles and scenery per the audit; `[matl_change]` swaps by variable.
- [ ] Interior light maps follow the interior-light script variables, not only the clock.

### Tests and docs
- [ ] Unit tests: overlay alpha = texture alpha x variable, per-mode light-map factor, `is_static_overlay` replacement keeps its test cases meaningful (the MAN SD83 test stays green).
- [ ] Update `sco.md` (remove "OPTS hides them", `Q-SCO-AS1`), `texture-quality.md`, `lighting-system.md`; mark the `dirt_norm` output as consumed.

## ✅ Acceptance Criteria

1. With `Dirt_Norm` forced to 1 via the control protocol on a vehicle that uses it, the dirt overlay is visible (mean luma of the body crop differs from `Dirt_Norm` = 0 by a documented threshold in the visual A/B harness); at 0 the overlay costs no draw call (entity count check).
2. `Rain_Window_Norm_Wetness` at 1 puts a visible overlay on the windows of one Citaro and one SD83, and `Dirt_Wiped` partly clears it; verified by two screenshots and a test on the alpha product.
3. For each `[nightmapmode]` value 0-4 at least one corpus object demonstrates the expected daylight and night behaviour; a table in the notes maps each mode to a test.
4. A scenery object with `[matl_lightmap]` and a vehicle with an interior light map light up at night and are dark by day; switching the variable changes the result within one frame.
5. The overlay setting Off leaves the render unchanged from today (screenshot difference below 0.5 % MAE) and Full costs no more than 0.5 ms of frame time on the RTX 3060 12 GB at 1920x1080 (measured with the lighting bench).
6. `sco.md` no longer claims that OPTS hides the overlays.

All gates pass (`cargo fmt`, `cargo clippy -D warnings`, `cargo test --workspace --all-features`, `./scripts/local-ci.sh`); no unsafe code; no OMSI asset committed.

## ⚠️ Risks & Mitigations

| Risk | Mitigation |
| :--- | :--- |
| Overlays add many transparent layers (43,968 alpha materials in the corpus) and overdraw | Build only parts whose product is above 0; setting levels; measure before defaulting to Full |
| Stock scripts need inputs OPTS does not supply yet and leave dirt at 0 | The audit lists each input; the control protocol can force the variable for acceptance tests |
| Mode semantics of `[nightmapmode]` are documented only by the files' prose | Experiment first, record it, behind one function |
| Transparency sorting artefacts on glass | Reuse the SD83 glass path (`crates/opts-bevy/tests/sd83_glass.rs`); sort checks in the A/B views |
