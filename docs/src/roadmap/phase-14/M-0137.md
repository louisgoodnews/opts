## 🎯 Objective

A player can load a vehicle, open the editor (the game paused), click a mesh (a seat, a mirror, the steering wheel), swap it for any `.o3d` of the catalogue, move, rotate or scale it with gizmos, see the change live, and save the result as a profile that the vehicle selection then lists as a derived vehicle.

**Rules fixed by the task:** a **patch layer**: a `VehicleProfile` (TOML) wraps the base OMSI vehicle; OPTS reads the base `.bus` and `.cfg` and applies the profile on top. The OMSI installation is never modified: profiles live in OPTS's data directory (`~/.local/share/opts/vehicles/`). A profile that fundamentally breaks the vehicle (missing script variables, say) is never saved without a warning. No custom 3D editor engine: reuse Bevy's ECS and `bevy_picking` / `bevy_gizmos` where available, otherwise state the dependency (a new workspace dependency needs the project lead's approval). This is a tooling and customisation phase; it is not mixed with the simulation-realism phases.

---

## 📦 Deliverables & Tasks

- [ ] Editor state or overlay as designed (paused game, free cursor, own input map), entered from the Alt menu.
- [ ] Mesh selection by picking or raycast: the mesh under the cursor highlights, a click selects it; the selection shows the mesh's `model.cfg` path.
- [ ] Mesh replacement from a catalogue browser panel (`opts-gui`) listing the `.o3d` files; the mesh swaps in real time; texture and material of the replacement are resolved like any other model.
- [ ] Transform gizmos (`bevy_gizmos`) for move, rotate and scale; the result is stored as `translation`, `rotation` (and scale) of a `[[mesh_overrides]]` entry.
- [ ] Undo and redo of edits; reset a mesh to the base.
- [ ] Profile saving to `~/.local/share/opts/vehicles/`, with the validation warnings of M-0136 shown before the save; the new profile appears in the vehicle selection.
- [ ] Tests: picking on fixture meshes (headless raycast), gizmo transform maths, the edit-to-TOML conversion round trip; the interaction path checked in the running game with screenshots.

---

## ✅ Acceptance Criteria

1. In the running game: load a bus, select the steering wheel, swap it for another `.o3d`, move it, save; the saved profile loads as a new vehicle with the change.
2. No file of the OMSI installation is written; breaking edits warn before the save.
3. All gates pass (`cargo fmt`, `cargo clippy -D warnings`, `cargo test --workspace --all-features`, `./scripts/local-ci.sh`).
