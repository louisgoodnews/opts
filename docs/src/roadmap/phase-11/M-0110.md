## 🎯 Objective

The player changes a vehicle's setvars while the session runs from the Alt menu, and the vehicle configuration manager understands more than binary options: integers, ranges and enumerations as `.cti` defines them.

**What exists already (build on it, do not duplicate):**

- [M-0078](../phase-10/M-0078.md) (planned) delivers the per-bus `SetvarCatalogue` (name, type, allowed values, label, default, group), a setvar editor in the wizard *What* step and *Pause > Vehicle*, and apply at spawn and live; [M-0077](../phase-10/M-0077.md) (planned) stores configurations that include setvars. `[setvar]` handling exists today as `OmsiSessionConfig.setvars`.
- Gap found while reading M-0078: its type list names `switch, choice, number` for generated controls but does not state how the `.cti` expresses integers, ranges or enumerations, nor how a value type is verified; this milestone owns that specification and extends M-0078's catalogue types accordingly. M-0078 also scopes the editor to the wizard and the Pause page; the Alt menu page (the in-game vehicle menu) is added here.
- The Alt menu hosts the vehicle menu pages ([in-game vehicle menu](../../architecture/in-game-vehicle-menu.md)).

---

## 🔍 Scope

**In scope:** document the `.cti` value syntax (integer, range, enum, boolean) with corpus counts; extend `SetvarCatalogue` entries with `ValueType::{Bool, Int{min,max,step}, Enum{labels}}`; generated controls (toggle, stepper/slider, dropdown); a runtime editor page in the Alt menu applying changes live to the active vehicle; round trip through configurations (M-0077) and session save (M-0069); protocol `vehicle.setvars` set with validation.

**Out of scope:** building the base catalogue and PDF cross-check (M-0078), configuration presets (M-0077), changing scripts, free-text setvar entry beyond the existing advanced field.

## 📦 Deliverables & Tasks

### Specification
- [ ] Docs first: `.cti` setvar value forms with corpus census (which vehicles use non-binary setvars, ranges, enum labels); mark unverified semantics ❓; note which require a respawn rather than a live change.

### Model and UI
- [ ] Extend the catalogue value types (after M-0078 lands, or together with it) and validate values on load, set and restore (out-of-range gives an error, never a clamp).
- [ ] Alt menu page *Setvars*: grouped controls generated from the catalogue, live apply where allowed, 'requires respawn' marker where not, reset to default.

### Persistence and tests
- [ ] Include typed values in configurations and session save; tests for each value type, invalid values and old-version files.

---

## ✅ Acceptance Criteria

1. The corpus census lists, per value form, the number of vehicles and setvars; the format page states what is verified and what is not.
2. On a reference bus with an integer or enum setvar, the Alt menu shows a stepper/dropdown with the declared range/labels; selecting a value changes the vehicle's script variable within one frame, or shows 'requires respawn' and applies on respawn.
3. An out-of-range value sent through `vehicle.setvars` is rejected with an error and does not change state; the same value read back after a valid set equals what was set.
4. A saved configuration and a saved session restore the typed values exactly (round-trip test for bool, int, enum).

All gates pass for milestones that change code (`cargo fmt`, `cargo clippy -D warnings`, `cargo test --workspace --all-features`, `./scripts/local-ci.sh`); no unsafe code; no OMSI asset committed.
