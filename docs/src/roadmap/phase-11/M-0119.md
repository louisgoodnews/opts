## 🎯 Objective

A repeatable review of the roadmap itself: after a phase closes, after every ten merged milestones or on request, a dev agent checks the roadmap against reality, proposes new milestones and drops stale ones, and hands the result to the project lead for approval. The deliverable is one prompt (P-1010) plus the references that make it part of the workflow.

**What exists already (build on it, do not duplicate):**

- [P-001 roadmap audit](../../../dev/prompts/core/P-001-roadmap-audit.md) reconciles ROADMAP, README, vision and milestone files (drift detection); it does not look for missing work, reprioritise or retire milestones.
- [P-002](../../../dev/prompts/core/P-002-next-milestone.md) picks and plans the next milestone; [P-006](../../../dev/prompts/core/P-006-roadmap-update.md) closes milestones.
- The task prompts P-1010..P-1013 in `docs/dev/tasks/` (merged 2026-10-25 from `fix/vehicle-animations`) are task prompts from the older numbering; the ID P-1010 for the review prompt is reserved by the project lead: check `docs/dev/prompts/` and `docs/dev/tasks/` for collisions first and note the outcome.

## 🔍 Scope

**In scope:** the prompt `docs/dev/prompts/process/P-1010-roadmap-review.md` (new category folder `process`), a short note in `CONTRIBUTING.md`, a reference in `docs/dev/prompts/workflow.md` (diagram and usage notes) and in the prompt README table, the cadence rule, the report format of a review.

**Out of scope:** running the review (the first run is a follow-up after this milestone), changing P-001, automatic scheduling, editing milestones without project lead approval.

## ✅ Acceptance Criteria

1. `docs/dev/prompts/process/P-1010-roadmap-review.md` exists with the standard prompt metadata table (ID, category, prerequisites, follow-up, last updated) and a fenced prompt block.
2. The prompt README, `workflow.md` and `CONTRIBUTING.md` each reference P-1010 and state the three cadence triggers exactly.
3. A dry run produces a review report that lists at least: milestones whose status contradicts merged code (with hashes), proposed new milestones, and ordering suggestions, and changes no milestone file.
4. Docs-only milestone: `python3 scripts/check_links.py` and `mdbook build docs` pass.

All gates pass for milestones that change code (`cargo fmt`, `cargo clippy -D warnings`, `cargo test --workspace --all-features`, `./scripts/local-ci.sh`); no unsafe code; no OMSI asset committed.
