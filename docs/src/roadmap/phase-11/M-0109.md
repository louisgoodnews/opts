## 🎯 Objective

Four small comfort features, tracked as one checklist: a door camera overlay, a smooth driver view, UI scale presets and UI font settings. Each item is independently shippable.

**What exists already (build on it, do not duplicate):**

- UI scale 75-200 % already exists as setting `ui_scale` (`UiScalePercent`, `apply_ui_scale`; [GUI design system §UI scale](../../architecture/gui-design-system.md), [M-0063](../phase-9/M-0063.md), a11y matrix in [M-0065](../phase-9/M-0065.md)); only presets and verification are new. No text renders below 12 px at 100 %.
- Camera views, per-vehicle driver cameras and the viewpoint editor (key 2, Tab) exist ([camera system](../../architecture/camera-system.md), M-0084); mirror cameras exist (2026-10 lighting work, `camera-system.md` Mirror cameras).
- The jitter seen while the driver view settles after spawn is being fixed at its root by the parallel branch `agent/spawn-drift-jitter`; this milestone starts only after that merge and covers what is left (smoothing of look-around and view transitions), not the root cause.
- Door open/close state is a script variable of the vehicle; door attachment points come from the vehicle's model/paths configuration ([model_cfg](../../formats/text/vehicles/model_cfg.md), [paths_cfg](../../formats/text/vehicles/paths_cfg.md), passenger cabin `[entry]`/`[exit]`). Offscreen render-to-texture exists for mirrors and the screen-capture path ([screen capture](../../architecture/screen-capture.md)).

---

## 🔍 Scope

**In scope:** (a) door camera: a picture-in-picture overlay showing the view at a chosen door while it is open or on a key; position from the door attachment in the vehicle data (verify in `model_cfg`/`paths_cfg` which entry carries it, docs first), reusing the mirror-camera render path; (b) smooth driver view: remaining smoothing after the root-cause fix, with a setting; (c) UI scale presets 100/125/150/200 % as chips in Settings > Interface mapped onto `ui_scale`, verified against the a11y layout matrix; (d) UI font and base font size settings (accessibility): choose among bundled/installed fonts and a base size 12-24 px.

**Out of scope:** a second free camera system, door cameras for walking pedestrians, changing the scale range of `ui_scale`, per-widget font overrides, fixing the spawn jitter itself.

## ✅ Acceptance Criteria

1. With the door camera enabled, opening the front door of the reference bus shows an overlay (one frame) whose view is positioned at the door attachment from the vehicle data; closing the door or toggling the key hides it; no overlay exists while the setting is off.
2. The overlay costs at most 1 ms per frame on the reference machine (measured with the performance overlay) and is not rendered while hidden.
3. After `agent/spawn-drift-jitter` is merged, a recorded 60 s drive in view 2 shows a per-frame camera position delta consistent with the vehicle motion within 2 mm; the smoothing item either meets this with `camera.smoothing` at its default or is closed as not needed with the measurement attached.
4. Clicking the 150 % chip sets `ui_scale` to 150 and the HUD, menus and mini map pass the M-0065 layout matrix at 1024x640 without overlap; the setting survives restart.
5. Choosing a base font size of 20 px enlarges all text of the HUD and settings page in the next frame; no text renders below 12 px; selecting an unavailable font keeps the previous one and shows an error toast.

All gates pass for milestones that change code (`cargo fmt`, `cargo clippy -D warnings`, `cargo test --workspace --all-features`, `./scripts/local-ci.sh`); no unsafe code; no OMSI asset committed.

## 📝 Notes & Logs

**2026-10-19, UI scale presets and fonts (branch `agent/qol-suite`).**

* **Presets:** `SettingDescriptor::presets` (new, generic) draws chips next to the stepper; `ui_scale` has 100/125/150/200 %. Test: a click on the 150 chip sets and stores the value and the marked chip follows. Matrices: `a11y_matrix` runs the scale test at 125 % as well, `hud_matrix` already covered 75 to 200 % up to 2560x1440. Checked live: `ui.click settings/interface/ui_scale/preset-150` gives `ui_scale` 150.
* **Fonts:** `opts_gui::fonts::UiTypography` (family and base size), applied by `sync_typestyle_tokens`; game side `ui_typography.rs` (settings sync, the `fonts/` folder, the refusal of an unknown family, the list of choices). Base size 12 to 24 px: all styles scale by size/14 and keep the 12 px floor. Checked live at 14, 20 and 24 px, with DejaVu Sans, and with an unknown family (value stays, error toast).
* **Found by the new HUD test:** at a base size of 20 px and more the status bar (two lines) grew into the camera label that sat at a fixed 84 px; the label now sits below the bar's measured height.
* **System fonts (decided 2026-10-19: use Bevy's feature):** `system_font_discovery` is enabled in the workspace `Cargo.toml` (adds `yeslogic-fontconfig-sys`, `roxmltree`, `objc2-core-text`; Linux needs `libfontconfig`, documented in [setup](../../contributing/setup.md)). The font row is now a combo box with a search field listing every family of the database (630 on the development machine); `ui.select` and `settings.set` work with system families; an unknown family is still refused with the toast. Checked live: Cantarell, C059 (a serif face) and Adwaita Sans applied, `No Such Typeface` refused. The `fonts/` folder stays for fonts that are not installed.
* **A side effect found by the HUD matrix:** with the feature an empty text node is one line high (22 px for a `Label`), without it zero. The viewpoint editor test measured the panel before its subtitle was filled in, so it saw 337 px; the real panel is 359 px, and the editor needs 500 px of layout height (was 470) to clear a toast: `editor_fits` in `hud_matrix` says so now.
* **Open in this milestone:** the smooth driver view (waits for `agent/spawn-drift-jitter`).

**2026-10-20, door camera (branch `agent/door-camera`).** See [camera system, door camera](../../architecture/camera-system.md) and the finding in [passengercabin_cfg](../../formats/text/vehicles/passengercabin_cfg.md): the door positions are the pathpoints of `[entry]` and `[exit]` (no separate attachment field exists, as the risk table expected); `camera.door_overlay` (off), F4 (cycle; reserved key), `camera.door` (protocol 1.17.0), 480 x 270 at 30 Hz, removed 5 s after hiding. Checked live on the BRT C2: F4 shows *Door 1: entry, front, right* with a picture from the door; 27 to 30 pictures a second; frame time 7.9 ms without, 8.6 ms with the overlay (limit 1 ms).
* **Choices to review:** the overlay is a HUD panel, not a widget of the profile registry (it appears and disappears with the door, a registry slot is fixed); the automatic choice is a heuristic on mesh animations because door variables have no common names, and it is **not verified with a real opening** (the C2's doors did not open headless; system tests with a faked leaf cover it); trailers' doors of articulated vehicles are not included; the key is F4 (F3/F4 were free).
