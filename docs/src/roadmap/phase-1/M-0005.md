## 🎯 Objective
Document the OMSI script language and the files it depends on, so that vehicle behaviour can later be mapped to Bevy systems.

## 🔍 Scope
**In Scope:**
- `.osc` script language, variable lists, constant files.

**Out of Scope:**
- An interpreter or Bevy mapping.

## ✅ Acceptance Criteria (Definition of Done)
1. Each spec follows the OPTS spec template (metadata table, overview, structure, field reference, examples, Open Questions, Provenance, related documents).
2. Every claim cites its evidence in the spec's Provenance; unknowns are listed as Open Questions.
3. No OMSI binary was inspected and no asset is included.
4. The spec is marked 🟡 Draft until the maintainer review and the relevant mutation tests are done; 🟢 Specified requires the spec's high-priority Open Questions to be resolved.

## ⚠️ Risks & Mitigations
| Risk | Mitigation |
| :--- | :--- |
| Specs derived from black-box observation may misread field meanings. | Corpus-wide structural checks; mutation-test kit (`opts-mutation-kit`) for behaviour; Open Questions kept honest. |
| Community documentation conflicts with the corpus. | Both are recorded in `docs/src/formats/community-crosscheck.md`; neither overrides the other until tested. |
