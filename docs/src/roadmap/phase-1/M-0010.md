## 🎯 Objective
Document the engine-level configuration files that have no spec: environment, weather and cloud configuration, scenario folders, input configuration, and plug-in variable declarations.

> ℹ️ **Scope origin.** Proposed in [`formats/gap-analysis.md`](../../formats/gap-analysis.md) and approved by the project lead on 2026-10-04 ("Proceed"). The ROADMAP gained the item through P-002 step 4.

## 🔍 Scope
**In Scope:**
- `envir.cfg`, `Weather/*` (`.owt`, `.dsc`, `clouds.cfg`, `ICAO.txt`), `Situations/*` and `Tutorials/*.osn`.
- `Inputs/keyboard.cfg`, `Inputs/gamectrler.cfg`, `options.cfg`.
- `plugins/*.opl` (text only).

**Out of Scope:**
- Any analysis of plug-in DLLs or executables.
- Sound and graphics option semantics beyond the keyword list.

## ✅ Acceptance Criteria (Definition of Done)
1. Every keyword of each file is listed with parameter counts and a corpus tally.
2. Meanings are stated only where the file's own explanation or the manual gives them; the rest is ❓.
5. Each spec follows the OPTS spec template (metadata, overview, structure, field reference, examples, Open Questions, Provenance, related documents), is linked from `SUMMARY.md` and the formats overview, and its Provenance states "No OMSI binaries were inspected".
6. `formats/gap-analysis.md` is updated to show the gap as closed (or partly closed).

## ⚠️ Risks & Mitigations
| Risk | Mitigation |
| :--- | :--- |
| Keyboard/controller files hold machine-specific values. | Document structure, not the user's bindings. |
| Shipped text is copyrighted. | Paraphrase; list only facts (names, counts, parameter lists); cite the file path. |
| Meaning inferred from names may be wrong. | Mark ❓; add Open Questions; propose a mutation test where behaviour matters. |
