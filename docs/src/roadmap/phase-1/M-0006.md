## 🎯 Objective
Reconcile every existing OPTS format specification with the public OMSI community wiki ("Dateiformate" and the 30 related pages listed by the project lead on 2026-10-04) and with the installed corpus. Each wiki fact is restated in our own words, attributed, verified against the corpus where measurable, and used to resolve or narrow Open Questions and to correct errors in the drafts. The result is a more accurate, better-attributed spec set — not new scope beyond the formats already in Phase 1.

> ℹ️ **Scope origin.** This milestone was requested directly by the project lead ("use these links to further analyze the OMSI installation and/or overhaul the existing documentation"). The ROADMAP had no matching item, so per the Universal Guardrails it is proposed for addition by P-006 (see Notes & Logs).

## 🔍 Scope
**In Scope:**
- Reading the 31 listed wiki pages (read-only, own-words fact extraction; CC BY-SA 4.0 attribution).
- Corpus cross-checks of every extracted claim that is measurable on the installed files.
- Updating the affected specs in `docs/src/formats/` with attributed facts (📚), corrected statements, and updated Open Questions tables.
- Extending `docs/src/formats/community-crosscheck.md` as the register of what the wiki added, confirmed or contradicted.
- Fixing relative links **only in files touched** by this milestone.

**Out of Scope:**
- Writing Rust code, tests, or crates.
- Copying wiki text, tables or examples (facts only).
- Reading any community **tool source code** (Blender plug-in etc.); wiki pages that merely describe tool usage are read as documentation.
- Creating the missing `SUMMARY.md` index pages, `coordinates.md`, or repairing the 48 broken `SUMMARY.md` links (tracked separately in the P-001 report).
- Running mutation tests in OMSI (owned by the project lead; kit already prepared).
- Any inspection of OMSI binaries.

## ✅ Acceptance Criteria (Definition of Done)
1. All 31 pages were read; each has an entry (even if "no new technical content") in the register in `community-crosscheck.md`.
2. Every wiki-derived statement in the repo is restated in our own words, marked 📚, and the page is listed in the Provenance of the spec that uses it. No sentence is copied.
3. Every numeric claim changed in a spec was recomputed from the corpus and the method is listed in that spec's Provenance.
4. Each affected spec's Open Questions table reflects what the wiki resolved or narrowed (IDs preserved).
5. Contradictions between wiki and corpus are recorded, not silently resolved.
6. No file other than `docs/` is modified; no OMSI asset is added; no OMSI binary is touched.
7. Relative links in every touched file resolve (checked by script).

## ⚠️ Risks & Mitigations
| Risk | Mitigation |
| :--- | :--- |
| CC BY-SA 4.0 share-alike contaminates MIT/Apache docs if wording is copied. | Facts only, own words, attribution; page content is read via a summariser, never pasted. |
| Wiki describes intended use, not behaviour; may be wrong or version-specific. | Mark 📚; corpus wins in conflicts; promote to 🟢 only after a mutation test. |
| Summariser drops or distorts details. | Treat as hints; cross-check measurable claims in the corpus; list the unmeasurable as ❓. |
| Scope creep into new pages/crate docs. | Updates limited to the specs listed; new topics become follow-ups via P-006. |
| Blender page leads toward reading GPL tool source. | Documentation page only; no repository or source is opened. |
