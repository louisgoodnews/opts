## 🎯 Objective

Trees sway in the wind. **OMSI does not animate trees** (checked 2026-10-26: none of the 7,546 tree-like `.sco` files of the installation has a `[newanim]`; `[tree]` billboards are static crossed quads), so this is an OPTS extension, switchable, that never changes what a file says.

---

## 📦 Deliverables & Tasks

### Phase A: Specification
- [x] [Vegetation wind](../../architecture/vegetation-wind.md): what OMSI does (nothing), the sway model, wind source (the weather's `[wind]`), setting, performance budget, what is out of scope.

### Phase B: `[tree]` billboards
- [ ] A tree material (`StandardMaterial` extended by a vertex stage) that bends the billboard: the base stays, the crown moves with the square of the height; each tree its own phase from its position; a slow sway plus a faster flutter.
- [ ] The same bend in the shadow and depth passes (the shadow moves with the crown).
- [ ] Wind direction and strength from the weather (`[wind]`), with a gentle breeze as the minimum; updated when the weather changes, not per frame on the CPU.
- [ ] Setting `graphics.tree_wind` (on by default), live; off keeps the trees still.
- [ ] Tests: the material's wind values follow the weather and the setting; a still tree's vertices are unchanged at strength 0.

### Phase C: Mesh trees (later)
- [ ] Trees modelled as `.o3d` meshes (trunk plus foliage cards): find a classification that does not catch other cutouts (fences, signs), then the same material.

## ✅ Acceptance Criteria
- On Berlin-Spandau and Grundorf, `[tree]` billboards sway visibly in a breeze, more under storm weather, and stand still with the setting off.
- The base of every tree stays fixed; no tree leaves its shadow behind.
- Frame time with the setting on is within 2 % of the setting off on the reference scene.
