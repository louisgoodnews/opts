## 🎯 Objective

Give every colour texture a correct mipmap chain. About 83 % of the corpus textures ship without one (≈ 120,000 JPEG/BMP/PNG/TGA files and 46,543 DXT files). **Hard limit (project lead, 2026-10-12): first-run work must never add more than 2 minutes** to loading a map.

---

## 📦 Deliverables & Tasks

### Phase A: Specification (this milestone file is the specification; refine before coding)
- [ ] Decide the DXT path by measurement: (1) decode to RGBA8 only, (2) decode → mips → re-encode to BC1/BC3 → derived cache, (3) anisotropy only. Candidate encoders to evaluate: `texpresso`, `intel_tex_2` (pure-Rust and build-time requirements decide). Record encode speed (MB/s) and quality (PSNR against the source's own level 0).
- [ ] Cache design: `~/.cache/opts/textures/<content-hash>-g<generator-version>.dds`, derived data on the user's machine only, never distributed; capped in size (default 4 GiB, least-recently-used eviction); invalidated by source hash or generator version; safe under concurrent processes (write to temp, rename).

### Phase B: Uncompressed textures
- [ ] `opts_bevy::texture::generate_mip_chain` (pure function): box or Kaiser downsampling with **sRGB-correct averaging**, correct handling of non-power-of-two sizes, optional alpha-coverage preservation (used by [M-0059](M-0059.md)).
- [ ] Applied to JPEG/BMP/PNG/TGA/uncompressed DDS images at load time, and in hot reload; textures that already have a full chain are untouched. Fix the silently dropped DDS chains found in M-0057.
- [ ] Tests: chain length and level sizes, sRGB averaging of a black/white checker (mid-grey ≈ 188, not 128), NPOT sizes, alpha untouched without coverage mode.

### Phase C: Block-compressed textures and the budget
- [ ] Chain generation for DXT1/3/5 files without one (per the Phase A decision), writing the derived cache.
- [ ] **The 120-second budget** is enforced in code, not by hope: a time-boxed worker pool (`rayon`, bounded threads) processes the textures of a loading map in priority order (player vehicle, start tile, then by distance). When 120 s of *added* time have elapsed the loader stops waiting; remaining textures use the fallback (decoded RGBA8 with a GPU/CPU chain if the VRAM budget allows, else no chain with anisotropic filtering) and the cache keeps filling in the background at low priority. The loading screen shows progress; a log line reports used and remaining budget.
- [ ] VRAM budget: a setting and an automatic cap based on the adapter's memory; the loader never exceeds it (falls back to option 3 for the largest textures).
- [ ] The budget is configurable *downward* only (`--texture-budget-s`); the upper limit is 120.

---

## ✅ Acceptance Criteria
- **Cold cache:** loading each of the three reference maps adds **≤ 120 s** compared with today's load time on the reference workstation (measured, reported per map; a deliberately slowed encoder in a test proves the budget cut-off).
- **Warm cache:** load time ≤ 110 % of today's.
- High-frequency energy on the distance views drops further compared with M-0057 alone; no visible mip-level popping in a fly-through video check.
- Cache tests: invalidation on source change and generator-version change, concurrent writers, eviction at the cap, corrupted file ignored and rebuilt.
- All gates pass; `docs/crates/opts-bevy.md` documents the cache and the budget.
