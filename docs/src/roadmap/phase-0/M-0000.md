## 🎯 Objective
Establish a robust, legal, and well-documented foundation for the OPTS project. This milestone ensures that the Rust workspace compiles, the documentation pipeline is automated, and the project governance (licensing, contributing guidelines, ADRs) is legally sound before any reverse-engineering or parsing code is written.

## 🔍 Scope
**In Scope:**
- Cargo workspace initialization and configuration.
- mdBook setup and GitHub Actions deployment.
- Project governance files (LICENSE, CONTRIBUTING, CODE_OF_CONDUCT).
- Initial Architecture Decision Records (ADRs).
- Core introductory documentation (Vision, Introduction, Glossary).

**Out of Scope:**
- Any reverse-engineering of OMSI file formats (`.o3d`, `.sco`, etc.).
- Writing any Rust parsing logic.
- Bevy integration or rendering code.
- Simulation logic.

## ✅ Acceptance Criteria (Definition of Done)
1. `cargo check` passes on a fresh clone of the repository.
2. The `mdBook` documentation builds successfully locally (`mdbook build`) and is deployed to GitHub Pages via CI.
3. ADR-0001 and ADR-0002 are committed, formatted correctly, and marked as "Accepted".
4. A new contributor can read `CONTRIBUTING.md` and understand exactly how to set up the project and submit a pull request.
5. The `ROADMAP.md` is visible and links correctly to the detailed milestone documents.

## ⚠️ Risks & Mitigations
| Risk | Impact | Mitigation |
| :--- | :--- | :--- |
| **Legal ambiguity regarding OMSI assets.** | High | ADR-0002 will explicitly state our clean-room policy: we will not distribute copyrighted assets, only the code to read user-provided assets. |
| **Over-engineering the workspace setup.** | Medium | Keep placeholder files minimal. Do not add complex CI logic (like testing) until there is actual code to test. |
| **mdBook CI issues on Windows/macOS.** | Low | Pin the `mdbook` version in the GitHub Action and use the official `peaceiris/actions-mdbook` action. |
