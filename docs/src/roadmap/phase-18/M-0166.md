## 🎯 Objective

OMSI 2 lists TrackIR 5 support as a base feature, as stated by its publisher. OPTS has no head-tracking code. Add head tracking as a camera input for players who own the hardware, so that the view follows the player's head.

## 🧩 Scope

Owner decision 2026-11-22: head tracking is in scope, under this milestone.

1. Specify the device interface from the vendor's public documentation, together with the driver's desk interface of [M-0168](M-0168.md), so that both device kinds share one design.
2. Map the head pose to the camera, with a setting to turn it on and off, and a centre (reset) action in the registry of [M-0142](../phase-7/M-0142.md).
3. Document the setting and the requirement in the Help overlay and the settings page.

**Out of scope:** any use of OMSI or LOTUS code or configuration for the device ([ADR-0002](../../adr/0002-clean-room-policy.md)).

## ✅ Acceptance Criteria

1. The device interface is specified in a design note, reviewed with [M-0168](M-0168.md).
2. With the feature off, the camera behaves as before (test).
3. With the feature on and a head pose supplied by a test source, the camera follows it, and a reset returns it to the centre (test).
4. A dated check with a real device is recorded in the notes. Until it exists, the feature is marked untested on hardware.
