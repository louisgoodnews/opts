## 🎯 Objective

OPTS has free drive and a sandbox, but no scenarios with goals, no challenge rules and no scoring. The vision asks for a scenario editor for community challenges. This milestone defines the scenario format and the first challenge rule set that the editor writes, and the scoring output that a run produces.

## 🧩 Scope

Owner decision 2026-11-22: the challenges and scoring part of ISS-048 is in scope, in the scenario editor, under this milestone.

1. Write the smallest challenge rule set in one page, using the data OPTS already models. A candidate is punctuality against the timetable and the number of passengers carried ([ISS-048](../../../dev/issues/ISS-048-challenges-and-scoring.md) item 2). The rules are OPTS's own.
2. Define the scenario as the editor writes it: the map, the start, the vehicle, the timetable and the goal. The format decision belongs to the save-format owner.
3. Decide the scoring output: a session summary shown at the end of a run, or a stored result. A stored result needs the save-format owner's decision first.
4. Record the owner's decision on the scenario editor's scope in the [vision](../../vision.md) and in the [editor README](../../editor/README.md), which name timetables, terrain, splines and traffic rules but not challenges or scores.

**Out of scope:** LOTUS challenge text, rules, layouts and maps ([ADR-0002](../../adr/0002-clean-room-policy.md)); multiplayer dispatch ([ISS-046](../../../dev/issues/ISS-046-multiplayer-co-op-dispatch.md), a vision item).

## ✅ Acceptance Criteria

1. The challenge rule set is written in one page, with each rule's input and the OPTS data it reads.
2. The scoring output (session summary or stored result) is decided and recorded in ISS-048.
3. The vision and the editor README state the decision, as ISS-048's "Done when" asks.
4. Any code change is in its own task of this milestone and names M-0172 in its commit.
