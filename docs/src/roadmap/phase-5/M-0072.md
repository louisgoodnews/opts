## 🎯 Objective

AI agents set **every** setting through the CLI as reliably as a user does through the settings page. Protocol 1.1.0 already has `settings.list/get/set/reset`; this milestone closes what is missing after verifying the reported gap.

## 📦 Deliverables & Tasks
- [ ] **Reproduce the report:** state exactly which setting or call failed for the reporter (settings not listed, `opts-cli` subcommand missing, change not applied, restart-required, revert prompt blocking) and record it in the field report.
- [ ] Settings that need the 15 s revert prompt (window mode/size): a `confirm` argument or `settings.confirm`/`settings.revert` so agents can finish the change; restart-required settings report `needs_restart`.
- [ ] Batch set and profiles: `settings.set_many` (atomic, validation errors per key), `settings.export`/`settings.import`, `settings.diff` against defaults.
- [ ] Coverage test: every registered setting is listed, gettable, settable and resettable through the protocol (enumerated from the registry, so new settings are covered automatically).
- [ ] Non-registry configuration reachable: language, theme mode, UI scale, content folders (OMSI folder), HUD widget switches, keybindings once M-0035 exists.
- [ ] Reference page and `help` stay generated from the descriptor table.

## ✅ Acceptance Criteria
- A scripted session sets every registered setting by name, reads it back and resets it; the coverage test fails when a setting is not reachable.
