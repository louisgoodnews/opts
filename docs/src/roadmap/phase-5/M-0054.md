## 🎯 Objective

Prove, object by object, that OPTS loads every scenery object (`Sceneryobjects/**/*.sco`, 55,664 files in the reference installation) correctly:
- A new crate `opts-benchmark` generates a map with one tile and places **one object at a time** on it.
- It renders the object off screen and checks placement, geometry and textures automatically against the object's own files.
- For objects with a script it checks the script's visible effect. Audio effects are recorded for a later check, not verified.
- The result is a per-object report and a list of failure categories, which Phase E fixes one category at a time.

The design is in [Scenery Object Load Verification](../../architecture/scenery-benchmark.md).

## ✅ Acceptance Criteria

- [ ] `opts-benchmark scenery run --omsi-path <root> --workers 3` completes the whole corpus unattended in **≤ 4 h** on the reference workstation (target ≈ 2 h), without writing to the OMSI installation, the repository or the user's settings.
- [ ] A crash or hang in one object costs one worker restart and is recorded as `F-CRASH` / `F-TIMEOUT`; the run continues and can resume.
- [ ] Every object has exactly one record with verdict `pass`, `fail`, `unknown` or `skipped`, its categories, tags, metrics, diagnostics and timing.
- [ ] Seeded faults are caught: on a test sample, a deliberately mirrored heading, a 2× scale, a 10 m offset, a removed texture and a removed mesh each produce the expected category.
- [ ] Two runs on the same commit and a warm decode cache give identical verdicts.
- [ ] The triage report (Phase D) exists and every failure category has a BOARD item.
- [ ] All new files follow the [coding standards](../../contributing/standards.md) (≤ 500 lines per file, ≤ 80 lines per function); CI gates pass.
