## 🎯 Objective

Make a running OPTS instance observable and controllable from the command line — by a human or an AI agent — and let edits to OMSI files take effect without a restart. Specified in [Control Protocol](../../architecture/control-protocol.md) and [Hot Reload](../../architecture/hot-reload.md).

---

## 🔍 Scope

**In Scope:**
- Part A — design documents and ADR-0006/0007.
- Part B — `opts-cli` client (one-shot, batch, REPL, JSON/human output, exit codes).
- Part C — `opts-bevy::control` server on std threads with a per-frame command drain; P1 commands.
- Part D — `opts-bevy::hot_reload`: watcher, debounce, validate-then-apply for meshes, textures, configs and tiles.
- Part E — agent documentation and example scripts; Part F — verification and final report.
- P2 commands (full entity/resource reflection, debug toggles, streaming) are specified but deferred.
