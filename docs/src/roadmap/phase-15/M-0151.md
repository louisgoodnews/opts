## 📦 Approach

1. **One batch per crate, largest first.** `opts-game` (305 entries) is split into three sub-batches by concern (in-game world, vehicle and scenery systems; UI, menu and session modules; settings, passengers, save and the rest). Each batch also covers the crate's test and example files.
2. **Split by concern boundary, never `part_1.rs`.** Each resulting module stays at or under 150 code lines, carries a `//!` module doc, and keeps existing public paths through `pub use`.
3. **Inline tests first.** Production files with inline `#[cfg(test)]` modules (104 files) move those modules to sibling `tests.rs` (the [M-0148](M-0148.md) rule) inside the same batch, because that alone drops many files under 150 lines.
4. **Ratchet shrinks per batch.** Each batch removes its files from `docs/dev/structure-known.txt`; no new entry is added and no entry grows. `python3 scripts/structure_audit.py check` must pass after every batch.
5. **Gate after every batch.** `./scripts/local-ci.sh` passes on each batch before the next starts; builds run one at a time through the sequential build wrapper.
