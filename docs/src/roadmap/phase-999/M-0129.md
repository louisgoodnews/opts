## 🎯 Objective

Every crate the audit flags (under 1,000 lines, over 10,000 lines, a name that does not match its content, a top-level module that shadows the crate) gets a decision (keep, merge, split, rename) with its reasons in an ADR. Execution happens only for the decisions the project lead approves, in a session of their own; the default is keep, because a crate split fragments the API, multiplies manifests and slows builds.

---

## 🔍 Scope

**In scope:** (a) the A4 crate table with each anomaly; (b) for each proposal an ADR (`docs/src/adr/`) with the benefit that justifies it (a heavy dependency used by part of the code, an API boundary the compiler should enforce, two tangled concerns), the cost (manifests, re-exports, compile times measured before and after), the migration for downstream code and the rollback; (c) execution of the approved ones with the same gates as the batches; (d) `Cargo.toml`, `docs/crates/*.md`, the crate graph (`scripts/crate_graph.py`) and `CONTRIBUTING.md` layer assignments updated.

**Out of scope:** any crate change without an ADR; changing crate boundaries to fix a size violation that a module split solves.

---

## 📦 Deliverables & Tasks

- [x] The crate anomaly table of the cycle-1 audit with a proposed decision per crate (default keep).
- [x] One ADR per merge, split or rename proposal; the project lead's decision recorded in each.
- [x] For approved proposals (none: every decision is keep): the change, the compile-time comparison (clean and incremental build of the workspace before and after), the updated crate graph check.
- [x] `CONTRIBUTING.md`, `docs/crates/*.md` and the layer table updated; downstream code migrated with no behaviour change.

---

## ✅ Acceptance Criteria

1. Every crate flagged by the audit has a recorded decision; every non-keep decision has an ADR with measured costs.
2. Executed changes pass the full gates, keep the public re-exports of the old crate paths where other crates depended on them (or migrate the dependants in the same change) and show no behaviour difference (tests, goldens).
3. `scripts/crate_graph.py` reports no unexpected edge; the crate count and layering match the updated documents.
4. If nothing is approved, the ADRs stand as decisions to keep and the milestone is done with that result.

All gates pass (`cargo fmt`, `cargo clippy -D warnings`, `cargo test --workspace --all-features`, `./scripts/local-ci.sh`); no unsafe code; no OMSI asset committed.

---

## ⚠️ Risks & Mitigations

| Risk | Mitigation |
| :--- | :--- |
| A split slows builds | Measure before and after; revert if the clean build gets slower without a dependency benefit |
| Downstream breakage | Re-export crate for one release or migrate dependants in the same change |
| Churn without benefit | The default is keep; a benefit must be stated and measured |

2. ADRs; checkpoint with the project lead.
3. Execute what is approved, one change per session; gates; update the graph and docs.
