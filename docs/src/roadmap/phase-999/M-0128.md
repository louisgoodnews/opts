## 🎯 Objective

The files that many crates use or that sit on hot paths are split with a written plan (batch 3), and the structural clean-up (batch 4) follows: single-file modules flattened, misplaced files moved to the sub-module they belong in, many-small-files modules consolidated where the split was arbitrary, and the test files over 500 lines split by concern. Behaviour and public paths stay as they are.

---

## 🔍 Scope

**In scope:** batch 3: the largest, most used files (the plan decides; candidates by size are `opts-traffic/src/agent.rs` (agent code and its tests in one file), `opts-game/src/in_game/vehicle_menu.rs`, `opts-game/src/in_game/omsi_world/vehicle.rs`, `opts-sim/src/vehicle/mod.rs`, `opts-catalogue/src/lib.rs`); batch 4: the A3 module findings and the A6 test-file findings of the audit; the function-size violations that a split exposes; documentation updates (`docs/crates/*.md`, architecture pages that cite file paths).

**Out of scope:** crate splits or merges (M-0129); changing a public API; performance work.

---

## 📦 Deliverables & Tasks

- [x] A per-file plan for batch 3 with the call graph of the public items, the re-export list and the tests to run (several per file), approved before the first move.

---

## ✅ Acceptance Criteria

1. Every file of batches 3 and 4 complies with the 500-line rule or has a recorded justification; the audit's count of files over 500 lines drops by at least the number of files in the batches.
2. All tests pass on every commit, including the replay determinism tests and the rig goldens; no golden file was regenerated by the cycle.
3. The public-API diff shows no removed items; the moved ones are listed with their kept paths.
4. Test files over 500 lines are split with the same set of test names (a before and after list of test names is equal).
5. `cargo doc --workspace --no-deps` builds without new warnings; every new module has a `//!` document.
6. Each commit has before and after counts; reverted attempts are listed.

All gates pass (`cargo fmt`, `cargo clippy -D warnings`, `cargo test --workspace --all-features`, `./scripts/local-ci.sh`); no unsafe code; no OMSI asset committed.

---

## ⚠️ Risks & Mitigations

| Risk | Mitigation |
| :--- | :--- |
| Hot-path files change frame cost through moved inlining | `#[inline]` kept as it was; a frame-time check on the benchmark scene before and after (no regression beyond noise) |
| Tests split by concern lose shared helpers | A `tests/common/` module with documented helpers; the test-name list comparison |
| Large moves hide a behaviour change | Moves are mechanical; any non-mechanical edit goes in a separate commit with its reason |

---

## 📋 Implementation Plan

1. Plan batch 3 per file; checkpoint.
2. Execute batch 3 one commit at a time with the full gates.
3. Batch 4 from the audit findings; docs updated with the moves.
4. Verification: audit comparison table, API diff, frame-time check; report; merge after approval.
