## 🎯 Objective

A repeatable measurement of the codebase's structure replaces the one-off audit of the task: one script produces the inventories the cycle protocol needs (files, functions, modules, crates, standards violations, test files) in the units of the project's own standard, writes the baseline report, and lets CI refuse a regression through a ratchet file. Without it a refactoring cycle cannot show that it improved anything, and the numbers drift back unnoticed between cycles.

---

## 🔍 Scope

**In scope:** `scripts/structure_audit.py` (Python 3, no dependencies, like `roadmap_audit.py` and `check_links.py`): (A1) every `.rs` file of `crates/` with total, code, comment and blank lines (code = non-blank, non-comment, excluding doc comments, as in standards section 3.7), generated files and fixtures excluded by an explicit marker list; (A2) every function over 60 lines of code (a brace-matching scan is enough; the 80-line rule is the hard limit, 40 the target); (A3) module directories: files, lines, largest file, single-file modules, files at a crate top that belong in a sub-module; (A4) crates: files, lines, public items, module depth, external dependencies, the anomalies the task lists (under 1,000 lines, over 10,000 lines, a top-level module shadowing the crate name, a name that does not match the `lib.rs` document); (A5) standards violations: the 500-line and 80-line rules, a module file without `//!`, a public item without `///`, `#[allow]` without a justification comment, `unwrap()`/`expect()` in library paths; (A6) test files over 500 lines with their test counts; the baseline report `docs/src/meta/structure-audit-<date>.md`; a **ratchet file** `docs/dev/structure-known.txt` holding the accepted violations (path and measure), checked by `scripts/local-ci.sh` so a new violation or a worsened known one fails the roadmap step.

**Out of scope:** any refactoring (that is M-0127 to M-0129); fixing the violations; a Rust-AST based tool (the scan is textual, its known blind spots are listed in the report); changes to `standards.md`.

## 📦 Deliverables & Tasks

- [x] `scripts/structure_audit.py` with sub-commands `report` (writes the Markdown report), `check` (the ratchet, exit 1 on a regression) and `json` (machine readable for the cycle comparison).
- [x] The measurement rules written into the script header: what counts as code, comments, blanks; which files are excluded as generated or fixture, and how they are marked.

- [x] `docs/src/meta/structure-audit-<date>.md`: the baseline (every file over 400 lines, every function over 60, the module and crate tables, the standards violations, the test files) and the five largest of each.
- [x] `docs/dev/structure-known.txt` seeded from the baseline, each entry with the planned cycle or a justification (a long lookup table, a golden file).
- [x] `scripts/local-ci.sh` runs `structure_audit.py check` as a step of its own; `docs/src/contributing/setup.md` and the CI description mention it.
- [x] Tests: the script on a fixture tree (a 600-line file, a 100-line function, a single-file module) reports exactly these; `check` fails when a known file grows and passes when one shrinks.

---

## ✅ Acceptance Criteria

1. `python3 scripts/structure_audit.py report` on the current tree gives the numbers of the phase README baseline (files, over 400/500/800/1,000, largest) within the difference between total and code lines, which the report states.
2. The report lists every file over 400 lines with total, code, comment and blank lines and every function over 60 lines of code with its concern word.
3. `check` passes on the seeded ratchet; adding a line to a known file beyond its recorded size, or a new 501st line of code to a file under the limit, makes it exit 1 with the file and the measure named.
4. The fixture test passes; the script runs in under 20 seconds on the repository.
5. `local-ci.sh` shows the new step and its failure is understandable without reading the script.

All gates pass (`cargo fmt`, `cargo clippy -D warnings`, `cargo test --workspace --all-features`, `./scripts/local-ci.sh`); no unsafe code; no OMSI asset committed.

## ⚠️ Risks & Mitigations

| Risk | Mitigation |
| :--- | :--- |
| The textual scan miscounts functions in macros | Blind spots listed in the report; the 80-line rule is checked as a warning list, only the file rule is ratcheted |
| The ratchet blocks unrelated work | Known entries may shrink freely; growth needs a ratchet edit with a reason in the commit; the file is human-readable |
| Counting rules differ from the standard's reading | The rules are quoted from `standards.md` in the header; a difference is a report note, not a silent choice |
