## 🎯 Objective

Users can save a **bus configuration** (bus, repaint, setvars) under a name and load it later in one step, instead of choosing everything by hand each time.

## 📦 Deliverables & Tasks
- [x] Data model (done 2026-10-18, [Bus Configurations](../../architecture/bus-configurations.md)) `BusConfiguration { id, name, vehicle (catalogue id), repaint, setvars (name → value), notes, created, last_used }`, versioned file in the user data directory next to the drive history, with validation on load (missing vehicle or repaint: reported with the error template, never a crash). The setvars stored are the user's overrides of the equipment options; since M-0078 they are validated against the vehicle's `SetvarCatalogue` (`opts_core::setvars`, kind and range per option; `vehicle.setvars` shows and changes them), so a configuration can be checked on load: a value the catalogue no longer accepts is reported, not applied.
- [x] UI (wizard *What* step done 2026-10-18: save, load, star, duplicate, delete with a second press; Alt menu *Configurations* page done 2026-10-20: list, spawn, save current, rename, delete with a second press; thumbnails later): in the wizard *What* step and in *Pause → Vehicle* a **Configurations** list: save current as…, load, rename, duplicate, delete (confirmation), mark favourite; *Start* from a configuration; thumbnails later.
- [x] Integrates with session vehicles (2026-10-20): `config.spawn` and the Alt menu's *Spawn* build a configuration as a new session vehicle; the session save stores each session vehicle with its repaint and options already ([M-0069](M-0069.md)).
- [x] Control protocol: `config.list/save/load/delete` (+ `update`, `duplicate`; protocol 1.9.0; done 2026-10-18).
- [x] Tests: round trip, missing content, old-version file (`bus_config/tests.rs`, `tests/config_protocol_tests.rs`).

## ✅ Acceptance Criteria
- A configuration saved in one session restores the same vehicle, repaint and setvars in another; deleting the bus or repaint on disk yields a clear message.
