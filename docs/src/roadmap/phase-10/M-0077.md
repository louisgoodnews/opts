## 🎯 Objective

Users can save a **bus configuration** (bus, repaint, setvars) under a name and load it later in one step, instead of choosing everything by hand each time.

## 📦 Deliverables & Tasks
- [ ] Data model `BusConfiguration { id, name, vehicle (catalogue id), repaint, setvars (name → value), notes, created, last_used }`, versioned file in the user data directory next to the drive history, with validation on load (missing vehicle or repaint: reported with the error template, never a crash). The setvars stored are the user's overrides of the equipment options; since M-0078 they are validated against the vehicle's `SetvarCatalogue` (`opts_core::setvars`, kind and range per option; `vehicle.setvars` shows and changes them), so a configuration can be checked on load: a value the catalogue no longer accepts is reported, not applied.
- [ ] UI: in the wizard *What* step and in *Pause → Vehicle* a **Configurations** list: save current as…, load, rename, duplicate, delete (confirmation), mark favourite; *Start* from a configuration; thumbnails later.
- [ ] Integrates with session vehicles: spawn a configuration into a running session; part of the session save ([M-0069](M-0069.md)).
- [ ] Control protocol: `config.list/save/load/delete`.
- [ ] Tests: round trip, missing content, old-version file.

## ✅ Acceptance Criteria
- A configuration saved in one session restores the same vehicle, repaint and setvars in another; deleting the bus or repaint on disk yields a clear message.
