## 🎯 Objective

Find out whether the plain texture atlas can serve as a second source of evidence for the UV decoder on meshes that have no plain twin, and if it can, use it to reduce the `Unreliable` and wrong `Recovered` vertices that still produce visible artifacts on the MAN NL/NG (wheel hexagon; roof glyph patches).

## 📦 Deliverables & Tasks

- [ ] **Phase 1, feasibility:** an `opts-core` example that ranks the true offset by texture continuity on the twin truth set (all 79 candidates per vertex); report `docs/src/meta/uv-texture-evidence-feasibility-YYYY-MM-DD.md` with top-1/top-3 rates by stage, texture variance and family. Go/no-go as defined in the design.
- [ ] **Phase 2, integration (only on go):** `TextureProbe` interface, texture term in the smooth stage, recalibrated `UvQuality` thresholds, cache v9, tests with a self-authored atlas fixture.
- [ ] **Phase 3, acceptance:** truth-set exact rate, per-family regression check, NG272 screenshots with the reinvestigation's camera script, expected-wrong-vertex count in the per-vehicle log line.
- [ ] **Docs:** update `uv-decoder.md`; add the result to the reinvestigation page.

## ✅ Acceptance Criteria

- Phase 1 report exists with numbers; a no-go closes the milestone with the report as its result.
- On go: truth-set exact rate (UV step) at least 85.14 % + 3 points, no family worse than -0.5 points, `./scripts/local-ci.sh` passes, cache version bumped.
- NG272 wheel and roof screenshots compared before/after; if the roof glyphs persist, a follow-up for material/texture selection is opened rather than reported as fixed.
- No OMSI asset committed; fixtures are self-authored.

## ❓ Open / ideas

- If the texture term works on vehicles but not scenery, enable it per family or by measured benefit, not by name (no per-vehicle special cases).
- A chain reconstruction of the scrambler would supersede this milestone; it is tracked in M-0079's open ideas.
