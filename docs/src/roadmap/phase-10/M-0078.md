## 🎯 Objective

Derive, per bus, the list of **setvars** it supports (name, type, allowed values/range, label, default, group) and let the user set them. Sources named by the project lead: the bus's **`.cti` files**, the **PDF manuals in the Add-ons**, and the **varnamelists** (there are lists named *visible*, which can also hold setvars).

## 📦 Deliverables & Tasks
- [ ] **Docs first:** specify how `[setvar]` is parsed today (`OmsiSessionConfig.setvars`) and what `.cti` files and varnamelists define (`docs/src/formats/`); find which varnamelists contribute (e.g. the *visible* lists) and how a setvar relates to script variables and to `[visible]`-style mesh switches.
- [ ] **Corpus census** (offline example in `opts-core`): per vehicle, collect candidate setvars from `.cti` and the varnamelists; statistics: distinct names, how many vehicles define them, value types, conflicts between sources.
- [ ] **PDF manuals:** decide under [ADR-0002](../../adr/0002-clean-room-policy.md) how the Add-on PDFs may be used (user-owned documentation, read at analysis time to cross-check names and meanings; **no text or images of the PDFs are committed**, only derived facts such as names and value meanings in our own words); record the decision in the spec.
- [ ] Data structure `SetvarCatalogue` built at catalogue refresh and cached per vehicle; unknown or unverified entries marked ❓.
- [ ] UI: a setvar editor in the wizard *What* step and *Pause → Vehicle* (generated controls: switch, choice, number), only for setvars the bus supports; unknown names can still be entered as advanced text with a warning.
- [ ] Apply: setvars reach the script variables and visibility lists at spawn and when changed live (where OMSI allows); control protocol `vehicle.setvars` get/set; part of configurations ([M-0077](M-0077.md)).
- [ ] Tests: catalogue for a sample of vehicles (synthetic fixtures), apply, and a regression of the existing setvar handling.

## ✅ Acceptance Criteria
- For the sampled buses the setvar list matches the cti/varnamelist/PDF evidence; setting a setvar visibly changes the bus (screenshot recipe) where the model reacts to it; the spec lists every unverified assumption.
