## 🎯 Objective

Derive, per bus, the list of **setvars** it supports (name, type, allowed values/range, label, default, group) and let the user set them. Sources named by the project lead: the bus's **`.cti` files**, the **PDF manuals in the Add-ons**, and the **varnamelists** (there are lists named *visible*, which can also hold setvars).

## 📦 Deliverables & Tasks
- [x] **Docs first:** specify how `[setvar]` is parsed today (`OmsiSessionConfig.setvars`) and what `.cti` files and varnamelists define (`docs/src/formats/`); find which varnamelists contribute (e.g. the *visible* lists) and how a setvar relates to script variables and to `[visible]`-style mesh switches.
- [x] **Corpus census** (offline example in `opts-core`): per vehicle, collect candidate setvars from `.cti` and the varnamelists; statistics: distinct names, how many vehicles define them, value types, conflicts between sources.
- [x] **PDF manuals:** decide under [ADR-0002](../../adr/0002-clean-room-policy.md) how the Add-on PDFs may be used (user-owned documentation, read at analysis time to cross-check names and meanings; **no text or images of the PDFs are committed**, only derived facts such as names and value meanings in our own words); record the decision in the spec.
- [x] Data structure `SetvarCatalogue` built at catalogue refresh and cached per vehicle; unknown or unverified entries marked ❓.
- [x] UI: a setvar editor in the wizard *What* step and *Pause → Vehicle* (generated controls: switch, choice, number), only for setvars the bus supports; unknown names can still be entered as advanced text with a warning.
- [x] Apply: setvars reach the script variables and visibility lists at spawn and when changed live (where OMSI allows); control protocol `vehicle.setvars` get/set; part of configurations ([M-0077](M-0077.md)).
- [x] Tests: catalogue for a sample of vehicles (synthetic fixtures), apply, and a regression of the existing setvar handling.

## ✅ Acceptance Criteria
- For the sampled buses the setvar list matches the cti/varnamelist/PDF evidence; setting a setvar visibly changes the bus (screenshot recipe) where the model reacts to it; the spec lists every unverified assumption.

## 📝 Decisions

- **PDF manuals (project lead, 2026-10-18):** the Add-on documentation PDFs may be read and fully comprehended for the analysis. They are bought and supplied by the original developers and contain no code, so reading them does not breach the clean-room policy ([ADR-0002](../../adr/0002-clean-room-policy.md)). What is recorded in the repository stays what the milestone says: derived facts such as setvar names, value meanings and groups, in our own words with the source named; no text or images of a PDF are committed.

## 📝 Outcome (2026-10-18)

- **Spec and census:** [setvars](../../formats/text/vehicles/setvars.md): 782 names on 1,095 vehicles, the value shapes (switches, choices from 0 or 1, codes, free numbers, two fractions), and the cross-check with twelve vendor documents (94 % of the documented names are set by the family's repaints, 98 % of the plain ranges contain the observed values).
- **Implemented:** `opts_core::setvars` (catalogue, curated data of 510 documented setvars), the wizard's equipment dialog with a switch, a choice box or a number field per option and defaults from the chosen repaint, stepping in the in-game vehicle menu, `vehicle.setvars` in the protocol (all or none, live in a drive), and an ordering fix for a race between the repaint discovery and the wizard's panels that the new systems made likely.
- **Live check on the real game** (`scripts/setvars-check.py`): 83 options for the Citybus o530 (the vendor documents 83); live changes reach the scripts; the vehicle's own ranges are enforced; the roof air-conditioning option visibly changes the model (about 50 times the noise), the front-face options were inconclusive from that camera angle (Q-SV02).
- **Not done here:** saving setvars with a bus configuration is [M-0077](M-0077.md); dependencies between options (one A/C value needs another option) and the German labels of the curated entries are not modelled; the curated meanings are unreviewed paraphrases of the vendors' documents.
