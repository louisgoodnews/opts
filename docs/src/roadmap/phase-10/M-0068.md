## 🎯 Objective

A session is a map plus **zero or more user vehicles**. The player can start with the map only, spawn buses during the session, remember all of them, switch the active one and respawn any of them, not only the active bus.

## 📦 Deliverables & Tasks
- [ ] **Map only:** the *What* step of the wizard offers *Drive without a vehicle* (and the vehicle selection screen of the legacy menu a matching button); the session starts with a free camera, the simulation running, no HUD instruments; a vehicle can be spawned later.
- [ ] **Session vehicle registry** (`SessionVehicles` resource): every user-spawned vehicle gets a stable session id, its catalogue reference, repaint, spawn point and live state (alive, destroyed, despawned by streaming). Parked/AI vehicles are not part of it.
- [ ] **Switch active vehicle:** list of session vehicles in *Pause → Vehicle* and a quick-switch key; switching moves the cockpit camera, HUD profile and input to the chosen one; the previous keeps its state (parking brake on, brought to rest by the physics, or stays under AI later).
- [ ] **Respawn any:** *Respawn* acts on a chosen session vehicle (reset to its spawn point or the current camera position) rather than only the active one; *Remove vehicle* with confirmation.
- [ ] Persistence hook: the registry is a section of the session save ([M-0069](M-0069.md)).
- [ ] Control protocol: `session.vehicles`, `session.spawn`, `session.switch`, `session.respawn`, `session.remove` plus tests.

## ✅ Acceptance Criteria
- A session can start without any vehicle, spawn two buses, switch between them and respawn the inactive one; all three verified through the control protocol and a headless test.
- No state leaks: despawning the session removes every session vehicle and its trailer chain; streaming a tile out never removes a user vehicle silently (a warning toast appears instead).
