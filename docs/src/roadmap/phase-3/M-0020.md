## 🎯 Objective

Implement spatial coordinate and orientation conversion systems in `opts-bevy` bridging OMSI's native world/vehicle coordinate frame ($X$ right, $Y$ forward, $Z$ up) into Bevy's right-handed engine frame ($X$ right, $Y$ up, $-Z$ forward). Provide pure vector and quaternion transformations, ergonomic ECS components (`OmsiTransform`, `OmsiCoords`), and Bevy synchronization systems registered via an `OptsCoordsPlugin`.

---

## 🔍 Scope

**In Scope:**
- Pure vector transformation functions converting between OMSI Z-up position vectors and Bevy Y-up vectors:
  - $x_{\text{bevy}} = x_{\text{omsi}}$
  - $y_{\text{bevy}} = z_{\text{omsi}}$
  - $z_{\text{bevy}} = -y_{\text{omsi}}$
  - Bidirectional inverse transformation ($x_{\text{omsi}} = x_{\text{bevy}}$, $y_{\text{omsi}} = -z_{\text{bevy}}$, $z_{\text{omsi}} = y_{\text{bevy}}$).
- Pure rotation conversion routines translating OMSI Euler angles (yaw, pitch, roll in degrees and radians) into Bevy `Quat`:
  - OMSI yaw ($\psi$, rotation around $+Z$) maps to Bevy rotation around $+Y$.
  - OMSI pitch ($\theta$, rotation around $+X$) maps to Bevy rotation around $+X$.
  - OMSI roll ($\phi$, rotation around $+Y$) maps to Bevy rotation around $-Z$.
- ECS components and types:
  - `OmsiCoords(pub Vec3)`: component tracking raw OMSI coordinates.
  - `OmsiTransform`: component representing translation, rotation (yaw, pitch, roll), and scale in OMSI space.
- Bevy ECS systems:
  - `sync_omsi_to_bevy_transforms`: updates Bevy's `Transform` when `OmsiTransform` is added or modified.
  - `sync_bevy_to_omsi_transforms`: back-propagates changes when Bevy `Transform` changes.
- Engine plugin `OptsCoordsPlugin` registering the systems into appropriate Bevy schedules (`PostUpdate` or `PreUpdate`).
- Unit and integration tests validating position transformations, quaternion equivalences, and ECS sync in a headless Bevy `App`.
- Documentation in `docs/crates/opts-bevy.md` and update to `docs/src/architecture/coordinates.md`.

**Out of Scope:**
- Map tile streaming / world chunk indexing (belongs in map streaming milestone; pending Q-M01).
- Vehicle dynamics / wheel physics integration (belongs in `opts-sim`).
- Mesh vertex coordinate conversion (already completed in M-0018).

## ✅ Acceptance Criteria (Definition of Done)

1. `cargo test -p opts-bevy` passes all unit and integration tests.
2. `omsi_to_bevy_pos` maps $(0, 10, 2) \to (0, 2, -10)$ exactly.
3. `bevy_to_omsi_pos(omsi_to_bevy_pos(p)) == p` within floating-point epsilon ($10^{-6}$).
4. `omsi_euler_to_bevy_quat` correctly maps positive yaw to counter-clockwise rotation around Bevy $+Y$.
5. Headless Bevy system updates `Transform` whenever `OmsiTransform` is mutated.
6. `cargo clippy --workspace --all-targets --all-features -- -D warnings` passes with zero warnings.
7. `cargo fmt --check --all` passes cleanly.
8. Zero `unsafe` code blocks across `opts-bevy` (`#![deny(unsafe_code)]`).
9. Zero `unwrap()` calls in library code paths.

## ⚠️ Risks & Mitigations

| Risk | Likelihood | Impact | Mitigation |
| :--- | :---: | :---: | :--- |
| **Gimbal lock in Euler conversions.** | Low | Medium | Use Quat internally for calculations and provide direct `Quat` conversion helpers; Euler angles only used for authoring/reading config values. |
| **System feedback loop (bidirectional sync).** | Medium | High | Use change detection filters (`Changed<OmsiTransform>`, `Changed<Transform>`) and avoid mutually triggering cycles in the same frame. |
| **Left-handed vs Right-handed rotation sign confusion.** | Medium | High | Validate cardinal rotations against explicit reference vectors with test assertions. |
