## 🎯 Objective

Bridge parsed 3D geometry from `opts-core` into Bevy's ECS rendering pipeline. Implement the mesh conversion bridge and native Bevy `AssetLoader` implementations in `opts-bevy` for OMSI's primary mesh formats (`.o3d` and `.x`). This milestone transforms left-handed, Y-up OMSI mesh buffers into native, right-handed, Y-up Bevy `Mesh` assets with correct vertex positions, normal vectors, UV coordinates, and inverted triangle winding orders per [`coordinates.md`](../../architecture/coordinates.md), registering them with Bevy's `AssetServer` via an `OptsMeshPlugin`.

---

## 🔍 Scope

**In Scope:**
- Coordinate conversion bridge function converting `opts_core::formats::o3d::O3d` to Bevy `Mesh`.
- Coordinate conversion bridge function converting `opts_core::formats::x::XMesh` / `XSubMesh` to Bevy `Mesh`.
- Left-handed to right-handed conversion:
  - Negation of $Z$ coordinates for vertex positions: $Z_{\text{bevy}} = -Z_{\text{omsi}}$.
  - Negation of $Z$ coordinates for vertex normals: $N_{z,\text{bevy}} = -N_{z,\text{omsi}}$.
  - Inversion of triangle winding order ($i_0, i_1, i_2 \to i_0, i_2, i_1$) to preserve front-face counter-clockwise rasterization.
  - Transmission of UV coordinates ($U, V$).
- Custom `AssetLoader` implementation for `.o3d` files in `opts-bevy`.
- Custom `AssetLoader` implementation for `.x` files in `opts-bevy`.
- Bevy plugin `OptsMeshPlugin` registering the asset loaders with the `App`.
- Unit tests validating coordinate negation, index reversal, and vertex attribute layouts.
- Integration tests validating loading and conversion inside a headless Bevy `App`.
- Module-level rustdoc and crate documentation update in `docs/crates/opts-bevy.md`.

**Out of Scope:**
- Full material/PBR shader generation and texture file loading (`.dds`, `.tga`, `.bmp`) (belongs in a subsequent asset/material milestone).
- Scenery object (`.sco`) or spline (`.sli`) asset loaders (belongs in a later milestone).
- Vehicle manifest spawning or dynamic simulation systems (belongs in `opts-game` / `opts-sim`).
- Binary file parsing logic (remains strictly inside `opts-core`).

## ⚠️ Risks & Mitigations

| Risk | Likelihood | Impact | Mitigation |
| :--- | :---: | :---: | :--- |
| **Inverted winding culling faces backwards.** | Medium | High | Reversing index order ($i_0, i_2, i_1$) directly offsets the single-axis $Z$-negation parity change, preserving CCW orientation. Validated by mutation tests T01/T02 in `coordinates.md`. |
| **Multi-material mesh splitting.** | Low | Medium | An `.o3d` file contains a single vertex stream but multiple face material indices. The loader can return the primary mesh or a composite/sub-mesh structure. Initial version produces a single combined `Mesh` or separate sub-meshes per material index. |
| **Async reader I/O errors.** | Low | Low | Wrap Bevy `AsyncReadExt::read_to_end` with strongly typed loader errors via `thiserror`. |

## 📋 Implementation Plan

### 1. Preconditions
- `opts-core` exports `O3d`, `XMesh`, `XSubMesh`, and their respective parse errors.
- `bevy` 0.14 dependency is configured in `crates/opts-bevy/Cargo.toml`.
- Coordinate conversion rules in `docs/src/architecture/coordinates.md` are documented and verified.

### 2. Sequence of Steps
1. **Implement Coordinate & Mesh Bridge (`crates/opts-bevy/src/mesh.rs`)**:
   - Write pure transformation functions mapping `O3d` and `XSubMesh` to Bevy `Mesh`.
   - Apply $Z$-negation to positions and normals.
   - Apply index reversal ($i_0, i_2, i_1$) for front-face CCW orientation.
2. **Implement Asset Loaders (`crates/opts-bevy/src/loader.rs`)**:
   - Implement `bevy::asset::AssetLoader` for `O3dAssetLoader` (`.o3d`).
   - Implement `bevy::asset::AssetLoader` for `XAssetLoader` (`.x`).
3. **Implement Bevy Plugin & Re-exports (`crates/opts-bevy/src/lib.rs`)**:
   - Create `OptsMeshPlugin` registering the loaders with Bevy's `App`.
   - Re-export public functions and types.
4. **Testing Suite (`crates/opts-bevy/tests/mesh_loader.rs`)**:
   - Unit tests verifying position/normal/index transformations.
   - Headless Bevy `App` integration tests verifying asset loading.
5. **Documentation & Quality Standards**:
   - Document `opts-bevy` in `docs/crates/opts-bevy.md`.
   - Run `cargo test`, `cargo clippy`, and `cargo fmt`.
