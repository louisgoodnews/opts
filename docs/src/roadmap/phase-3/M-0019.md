## 🎯 Objective

Enable visual texturing and material rendering in `opts-bevy` for OMSI 3D assets. Implement content-sniffing texture decoders and a native Bevy `AssetLoader` for DirectDraw Surface (`.dds`) and legacy image formats (`.bmp`, `.tga`, `.png`, `.jpg`), and build the material bridge mapping `O3d` and `XMesh` material definitions into native Bevy `StandardMaterial` assets with accurate diffuse color, emissive lighting, transparency modes (`AlphaMode`), and texture bindings.

---

## 🔍 Scope

**In Scope:**
- Texture content format sniffing (inspecting magic bytes `DDS `, `BM`, `\x89PNG`, `\xFF\xD8`, and TGA headers) to robustly load the 1,170+ corpus assets whose file extensions do not match their contents.
- DirectDraw Surface (`.dds`) loading and decoding into Bevy `Image`:
  - DXT1 / BC1 (`TextureFormat::Bc1RgbaUnormSrgb`), DXT3 / BC2 (`TextureFormat::Bc2RgbaUnormSrgb`), DXT5 / BC3 (`TextureFormat::Bc3RgbaUnormSrgb`).
  - Uncompressed 32-bit (`A8R8G8B8`, `A8B8G8R8`) and 24-bit (`R8G8B8`) formats converted to `Rgba8UnormSrgb`.
  - Single-channel 8-bit alpha masks (`A8`) converted to `TextureFormat::R8Unorm` or single-channel alpha textures.
- Fallback image decoding for `.bmp`, `.tga`, `.png`, `.jpg` via the `image` crate into GPU-ready Bevy `Image` assets.
- Bevy `AssetLoader` implementation (`DdsAssetLoader` and general image loader) registered in `opts-bevy`.
- Material conversion bridge:
  - Converting `opts_core::formats::o3d::Material` to Bevy `StandardMaterial`.
  - Converting `opts_core::formats::x::XMaterial` to Bevy `StandardMaterial`.
  - Translating diffuse RGBA, specular shine/roughness, and emissive RGB.
  - Setting appropriate `AlphaMode` (`Opaque`, `Mask(0.5)`, or `Blend`) based on texture format and material flags.
- Plugin registration (`OptsMaterialPlugin` or unified `OptsAssetPlugin`).
- Unit and integration tests validating header sniffing, DDS decoding, material mapping, and headless Bevy `App` asset loading.
- Documentation update in `docs/crates/opts-bevy.md`.

**Out of Scope:**
- Dynamic texture generation / text texture rendering (belongs in a later UI/script texture milestone).
- Full vehicle `model.cfg` animation/hierarchy spawning (belongs in a later vehicle spawning milestone).
- Sound file loading (`.wav`) (belongs in an audio milestone).
- Ground terrain blending shaders (belongs in map streaming milestone).

## ⚠️ Risks & Mitigations

| Risk | Likelihood | Impact | Mitigation |
| :--- | :---: | :---: | :--- |
| **Bevy image format GPU support.** | Medium | Medium | Bevy supports standard compressed formats (`Bc1RgbaUnormSrgb`, `Bc3RgbaUnormSrgb`) on desktop backends (Vulkan, DX12, Metal). For unsupported platforms, provide uncompressed fallback conversion. |
| **Extension mismatch crashes.** | Medium | High | 1,170 corpus files have wrong extensions (e.g. BMP in `.dds`). Sniffing magic bytes before choosing decoder eliminates extension mismatch errors. |
| **Bottom-up UV orientation in BMP/TGA.** | Medium | Medium | Standardize V coordinate orientation or flip raster rows when loading uncompressed BMP/TGA images. |
| **Alpha mask textures (`A8`).** | Low | Low | Convert 8-bit alpha masks to `R8Unorm` or `Rgba8Unorm` with opaque white RGB and alpha mapped to A. |

## 📋 Implementation Plan

### 1. Preconditions
- Milestone M-0018 complete (3D mesh loaders in `opts-bevy`).
- Dependencies `ddsfile` and `image` configured in `crates/opts-bevy/Cargo.toml`.
- Texture format facts from `docs/src/formats/textures.md` validated against corpus.

### 2. Sequence of Steps
1. **Implement Texture Sniffing & Decoding (`crates/opts-bevy/src/texture.rs`)**:
   - Write magic byte sniffing function.
   - Implement DDS decoding using `ddsfile` to produce Bevy `Image` (setting width, height, format, data).
   - Implement generic image decoding using `image` crate as fallback.
2. **Implement Bevy Texture Asset Loader (`crates/opts-bevy/src/loader.rs`)**:
   - Implement `DdsAssetLoader` implementing Bevy's `AssetLoader`.
   - Wire content sniffing to route BMP-in-DDS files to the appropriate decoder.
3. **Implement Material Conversion Bridge (`crates/opts-bevy/src/material.rs`)**:
   - Implement `o3d_material_to_standard_material` and `x_material_to_standard_material`.
   - Calculate perceptual roughness, base color, emissive color, and alpha modes.
4. **Update Plugin & Exports (`crates/opts-bevy/src/lib.rs`, `plugin.rs`)**:
   - Add `OptsMaterialPlugin` (or expand `OptsMeshPlugin` / bundle into `OptsAssetPlugin`).
   - Re-export public conversion functions and loaders.
5. **Testing Suite (`crates/opts-bevy/tests/texture_material.rs`)**:
   - Write unit tests for sniffing, DDS decoding, and material construction.
   - Write headless Bevy `App` integration test loading a `.dds` asset.
6. **Documentation & Validation**:
