## 🎯 Objective

A driving-safe HUD built from registered widgets, with help, hints and feedback that fit the moment.

## 📦 Deliverables & Tasks
- [ ] Instrument token set with day/night variants; instrument cluster (speed, gear, brake state, units; RPM when the simulation provides it, hidden otherwise rather than "--").
- [ ] `HudWidget` / `HudProfile` registry and RON profiles for the vehicle types in the corpus; user can switch widgets on/off.
- [ ] Slots: status bar (fades), alerts (one at a time, critical sticky), hints (fade), camera label.
- [ ] **Help and controls overlay** generated from the active bindings and vehicle type; F1 per D-UI-06; *Report an issue* with a titled dialog and a visible preview, no silent failure (F18).
- [ ] Developer panel replaces the always-visible F10 block (off by default); toasts stack without overlap and below modal layers (F22).
- [ ] Vehicle menu integrated into *Pause → Vehicle*; menu and pause always release/restore the cursor and simulation state exactly.
- [ ] HUD review checklist for UI-P13 and a measurement of glance time in the usability test.

## ✅ Acceptance Criteria
- The HUD never takes focus, never moves, never covers the centre of the view; contrast ≥ 4.5:1 on both a bright and a dark scene background (rendered test).
- Every key that does something is listed in the help overlay (generated, so it cannot lag).
- No permanent debug output in a default run.
