## 🎯 Objective

The loading screen names the vehicle that was selected (or *no vehicle*) from the first frame. Today it shows the MAN SD77 first and changes to the real vehicle after about 70 % of the progress.

## 📦 Deliverables & Tasks
- [x] Find the default (hard-coded or fallback vehicle text) and the point in the load sequence where the real selection reaches the screen.
- [x] Pass the selection (catalogue id, display name, repaint, or *none*) in the load request so the loading screen reads it before any loading step starts; remove the default.
- [x] Map-only start ([M-0068](../phase-10/M-0068.md)) shows 'No vehicle'.
- [x] Test: the first rendered loading frame names the selected vehicle for three different selections; a source test forbids a default vehicle name in the loading screen.

## ✅ Acceptance Criteria
- The vehicle line never changes during loading and never shows a vehicle that was not selected.

## 📝 Implementation notes (2026-10-13)

* Cause: the loading screen read `InGameSessionInfo.vehicle_name`, first the wizard's key (or the `NewGameSetup` default `MAN SD200 - SD77`), later overwritten by the loaded manifest's name at about 70 %. Now `setup_in_game_session` decides the line once (catalogue name and repaint of the selection, the `--vehicle-path` file stem, or *No vehicle*) and nothing writes it again. `NewGameSetup::default()` names no vehicle.
* Tests: `loading_tests::the_first_loading_frame_names_the_selected_vehicle_or_none_and_never_changes` (three vehicles and none, first frame and the whole load), source test for default names in the loading and HUD sources.
