## 🎯 Objective

Other people and AI agents can add or improve a language **without touching Rust code**, by writing a plain, validated text file and dropping it in a folder; the app finds it, validates it, lists it in *Settings → Interface → Language* and never crashes on a bad pack.

## 📦 Deliverables & Tasks
- [x] **Research and decision** (documented in `docs/src/architecture/localisation-packs.md`): format options (Fluent `.ftl` as used today, flat JSON `{key: text}`, JSON with metadata and plural forms, PO/XLIFF, TOML) compared on convenience for humans and AI agents, validation, plurals and variables, tooling, diff-friendliness; decide a primary format and whether a JSON interchange form is offered (recommended starting point: keep Fluent as the runtime format, offer lossless JSON export/import for contributors and AI).
- [x] **Pack layout:** a folder per language in the user data directory (`<data>/lang/<code>/`) with `pack.json` (code, English name, native name, direction, version, authors, licence, base version of the strings it was made against) plus string files; discovery at start and on demand (*Reload languages*); packs override or extend built-in tables; fallback chain *selected → English*; missing keys fall back per key and are listed.
- [x] **Validation:** syntax errors, unknown keys, variable mismatch against English, empty strings, suspicious length; errors are reported per file and line with the error template, never crash; invalid keys are skipped.
- [x] **Tooling:** `opts-tools l10n export --lang <code> --format json|ftl` (template with all English strings, context comments and variable lists), `l10n check <pack>` (completeness and validation report, exit code for CI), `l10n new <code>` (scaffold from English), `l10n stats`; machine-readable output so AI agents can fill a template and verify it.
- [x] **UI:** language list shows built-in and installed packs with completeness percentage and author; a pack with gaps shows English for the gaps; right-to-left packs are detected and reported as not yet supported (red text per the UI standards) unless implemented; fonts for scripts not covered by the bundled font are reported.
- [x] **Docs:** update the translating guide with a step-by-step contributor and an AI-agent workflow, a pack schema reference, and the licence expectations (contributed text is licensed as the project).
- [x] Control protocol: `l10n.languages`, `l10n.set`, `l10n.reload`, `l10n.report`.
- [x] Tests: pack discovery, override and fallback, broken-file tolerance, export/import round trip, completeness report.

**Delivered** (2026-10-13): Fluent stays the runtime format, plus the lossless JSON form `opts-l10n/1` (decision and comparison in the architecture page); packs in `<data>/lang/<code>/` with `pack.json`; per-key fallback; every check with file, line, key and code; `opts-tools l10n export|check|new|import|stats` with `--json` and exit codes; the language list in *Settings → Interface → Language* with completeness, authors, problems, *Reload languages*; `l10n.languages|set|reload|report`; tests `opts-core l10n`, `opts-tools l10n`, `opts-game --test language_packs`.

**Open (not part of this milestone's scope):** right-to-left layout and fonts for scripts beyond Latin, Greek and Cyrillic (packs are listed with a red note and RTL packs cannot be selected); number/date/unit formatting per language; the project lead's trial in the running app with a real second language.

## ✅ Acceptance Criteria
- A contributor (or an AI agent) can create a new language from the exported template, validate it with `opts-tools l10n check`, drop it into the user folder and select it in the running app without recompiling; a broken pack never prevents start.
