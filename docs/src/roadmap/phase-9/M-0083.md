## 🎯 Objective

Other people and AI agents can add or improve a language **without touching Rust code**, by writing a plain, validated text file and dropping it in a folder; the app finds it, validates it, lists it in *Settings → Interface → Language* and never crashes on a bad pack.

## 📦 Deliverables & Tasks
- [ ] **Research and decision** (documented in `docs/src/architecture/localisation-packs.md`): format options (Fluent `.ftl` as used today, flat JSON `{key: text}`, JSON with metadata and plural forms, PO/XLIFF, TOML) compared on convenience for humans and AI agents, validation, plurals and variables, tooling, diff-friendliness; decide a primary format and whether a JSON interchange form is offered (recommended starting point: keep Fluent as the runtime format, offer lossless JSON export/import for contributors and AI).
- [ ] **Pack layout:** a folder per language in the user data directory (`<data>/lang/<code>/`) with `pack.json` (code, English name, native name, direction, version, authors, licence, base version of the strings it was made against) plus string files; discovery at start and on demand (*Reload languages*); packs override or extend built-in tables; fallback chain *selected → English*; missing keys fall back per key and are listed.
- [ ] **Validation:** syntax errors, unknown keys, variable mismatch against English, empty strings, suspicious length; errors are reported per file and line with the error template, never crash; invalid keys are skipped.
- [ ] **Tooling:** `opts-tools l10n export --lang <code> --format json|ftl` (template with all English strings, context comments and variable lists), `l10n check <pack>` (completeness and validation report, exit code for CI), `l10n new <code>` (scaffold from English), `l10n stats`; machine-readable output so AI agents can fill a template and verify it.
- [ ] **UI:** language list shows built-in and installed packs with completeness percentage and author; a pack with gaps shows English for the gaps; right-to-left packs are detected and reported as not yet supported (red text per the UI standards) unless implemented; fonts for scripts not covered by the bundled font are reported.
- [ ] **Docs:** update the translating guide with a step-by-step contributor and an AI-agent workflow, a pack schema reference, and the licence expectations (contributed text is licensed as the project).
- [ ] Control protocol: `l10n.languages`, `l10n.set`, `l10n.reload`, `l10n.report`.
- [ ] Tests: pack discovery, override and fallback, broken-file tolerance, export/import round trip, completeness report.

## ✅ Acceptance Criteria
- A contributor (or an AI agent) can create a new language from the exported template, validate it with `opts-tools l10n check`, drop it into the user folder and select it in the running app without recompiling; a broken pack never prevents start.
