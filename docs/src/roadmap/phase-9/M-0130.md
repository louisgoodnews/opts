## 🎯 Objective

A user can save map-specific settings, and the map selection screen tells them, before the map is loaded, how heavy it is and which settings will matter most. A **Map Load Profiler** reads the map's files from disk (static profile) and remembers the frame time of the last session on that map (dynamic profile), and a small heuristic engine turns both into recommendations. Profiles apply for one session only; the global settings return when the user leaves to the main menu.

---

## 🔍 Scope

**In scope:** the profile scope (which settings may differ per map), a TOML profile store with a fallback chain, applying and restoring settings around a session, the static profiler, the dynamic profiler, the heuristic engine, the *Map Configuration* modal in the map selection screen.

**Out of scope:** UI themes, language, key bindings and accessibility settings in a profile; changes to the global settings file when saving a profile; hard-coded map names or object counts; profiling by loading the map.

**Design rules fixed by the task:**

- **Two axes of identity:** a profile is keyed by `map_id` **and** `chrono_id` (`default` when no Chrono is active). Fallback chain: `{map_id}_{chrono_id}.toml`, then `{map_id}_default.toml`, then the global settings.
- **Not every setting belongs in a profile:** only settings that affect map performance and simulation. Phase A sorts every existing setting into *always global* (language, UI scale, key bindings), *map-profile eligible* (view distance, shadow quality, AI density, reflection resolution) and *map-locked* (simulation tick rate) and proposes the exact `MapProfile` struct.
- **Non-destructive:** a loaded profile overrides the global settings for the session; leaving to the main menu restores them.
- **The profiler never freezes the UI:** static profiling reads the `.map`, `.cfg` and AI list files directly (under 100 ms per map, never on the main thread, see M-0088); the dynamic part is recorded in the background during play.
- Files live under `~/.local/share/opts/profiles/` (layout decided in phase A, e.g. `profiles/{map_id}/{chrono_id}.toml`, metrics in a `metrics.toml` beside them).

## 📦 Deliverables & Tasks

**Phase A: design (checkpoint 1: wait for the project lead's approval before phase B)**

- [ ] A1 `docs/src/architecture/map-profiles.md`: the three-bucket classification of every existing setting and the Rust `MapProfile` struct.
- [ ] A2 File format (TOML), directory layout, location of the dynamic metrics.
- [ ] A3 Lifecycle: when a profile is loaded and applied (map selection, map finished loading, return to the main menu) and the fallback chain.
- [ ] A4 `MapLoadProfile { object_count, spline_count, ai_vehicle_count, map_size_km2, avg_frame_time_ms: Option<f32> }` and the heuristic engine (starting points: more than 50,000 objects advises lower view distance and shadow quality; more than 200 AI vehicles advises lower AI density; an average frame time above 33 ms advises a *Performance* profile).
- [ ] A5 The modal: title *Map Configuration*, profiler feedback, profile dropdown, actions *Apply Selected*, *Create New from Current*, *Delete*, *Cancel*.

**Phase B: implementation (checkpoint 2: report with screenshots of the modal on a light and a heavy map, wait for approval)**

- [ ] B1 `MapProfile`, `ProfileManager`, `MapLoadProfile`; TOML load and save; the fallback chain.
- [ ] B2 Settings integration: the map loading sequence asks the `ProfileManager`; settings are applied to the session state; the pre-profile settings are kept and restored on exit.
- [ ] B3 Static profiler: a fast reader in `opts-core` counting `[object]` and `[spline]` records in `.map` tiles without loading 3D data, and an AI density counter over the AI list files.
- [ ] B4 Dynamic profiler: a background system averaging the frame time during play, saved on map exit and read by the modal on the next visit.
- [ ] B5 The modal with profiler feedback (static counts, last frame time, recommendations) and working *Apply Selected* / *Create New* / *Delete*.

**Phase C: verification (final report, merge `--no-ff` after approval)**

- [ ] C1 Lifecycle test: create a profile with low view distance, start the map (low), exit (global unchanged), delete the profile, start (global applies).
- [ ] C2 Chrono test: a profile for the default Chrono, start in a specific year (fallback), create a year profile (applies).
- [ ] C3 Accuracy test: a known dense map (Berlin-Spandau) shows high counts and recommends performance settings; after 30 s of play the frame time updates; a known sparse map (Grundorf) shows low counts and recommends full quality.
- [ ] C4 Automated tests: profile discovery, loading and fallback; the counting logic on a fixture `.map`; the heuristic engine for given metrics.
- [ ] C5 Docs: `map-profiles.md` finished, `docs/crates/opts-game.md` updated, `main-menu.md` if it documents map selection.

## ✅ Acceptance Criteria

1. `MapProfile` and `MapLoadProfile` exist; profiles save to and load from `~/.local/share/opts/profiles/`; the fallback chain holds for map, Chrono and global.
2. Global settings are untouched by saving a profile and restored after a session that used one.
3. The static profiler estimates a map's load in under 100 ms and never runs on the main thread; the dynamic profiler records and persists the frame time.
4. The map selection screen has the modal; the user can create, apply and delete profiles; the feedback shows counts, last frame time and recommendations.
5. All gates pass (`cargo fmt`, `cargo clippy -D warnings`, `cargo test --workspace --all-features`, `./scripts/local-ci.sh`); merged to `master` with `--no-ff`.

---

## ⚠️ Risks

- Chrono folders change a map's content: a profile for the wrong Chrono must never apply silently (the fallback is shown in the modal).
- Counting records without parsing them may differ from the loader's own counts: the tests compare both on a fixture.
- Applying settings per session touches systems that read settings at start-up (view distance, shadows): phase A lists which settings can change live and which need the profile applied before the load.
