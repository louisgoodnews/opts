## 🎯 Objective

Long dropdowns (the 16 start points of a map, language lists) are **searchable and scrollable**, and the catalogue summary in *Settings → Content* states what it counts.

## 📦 Deliverables & Tasks
- [x] **Scrolling** of the combobox menu (wheel, keyboard focus, scroll bar) — fixed on `fix/dropdown-scroll` (R-28).
- [x] **Search in dropdowns:** when a menu has more than N options (default 8) a search field at the top filters the options as the user types (case- and diacritics-insensitive, 150 ms debounce), keeps the selection if still visible, supports arrow keys and Enter, shows 'No match' and a clear button; opening focuses the field; short lists stay plain; localised placeholder ('Search…'); accessible name; works with the control protocol (`ui.text` into the search field, `ui.select`).
- [x] Test: filter, keyboard flow, selection retained, 16-option wizard start-point list; golden/a11y matrix unchanged for short lists.
- [x] **Catalogue count (R-24):** *Settings → Content* said '75313 Karten, Fahrzeuge und weitere Inhalte gefunden' next to 'Home: 43 maps · 947 vehicles'; the number is the total of catalogue entities of every kind (scenery objects, splines, textures, sounds, humans, …), not maps. Show a breakdown by kind (maps, vehicles, scenery objects, splines, other) from the catalogue, explain 'files' versus 'entries', and keep both numbers consistent with Home (German and English strings).

## ✅ Acceptance Criteria
- A dropdown with 16 entries can be filtered by typing and scrolled; the Content page shows maps and vehicles separately with the same numbers as Home.

## 🧾 Implementation notes

- **Combobox** (`opts-gui/src/components/combobox.rs`): menus with more than `search_threshold` options (default 8, `ComboboxBuilder::with_search_threshold`) get a compact text field above the scrolling list (`ComboboxSearch`, `ComboboxList`) and a *No match* row. Filtering matches every word of the query case-, diacritics- and punctuation-insensitively (`l10n/fold.rs`; `sud` finds `Süd`, `ubhf` finds `U-Bhf.`), 150 ms after the last keystroke; options are hidden, never removed, so `ComboboxMenuItem` indices and `ui.select` keep working. Opening focuses the field and scrolls the selected option into view; Down moves into the list, Enter picks the selected (else first) match, Esc clears the query first and closes second, closing resets the query.
- **Strings**: `widget-combobox-search`, `widget-combobox-search-label` (accessible name, also the stable id slug `<combobox id>/textbox:widget-combobox-search-label`) and `widget-combobox-no-match` in `en.ftl`/`de.ftl` (en-XA derives from English).
- **Control protocol**: `ui.text` into the search field by that id; `ui.select` now also accepts the id of the combo box root (the id screens set), not only its header.
- **Catalogue**: `Catalogue::kind_counts()` counts maps and vehicles with the same joins as the menu lists (so Settings equals Home), plus scenery objects, splines and the rest; Settings → Content shows the breakdown line and a files-versus-entries line.
- **Live check** (Berlin-Spandau, 16 start points; Settings → Content, German and English): Settings said `43 maps, 947 vehicles, 55664 scenery objects, 15291 splines and 3368 other entries`, 75313 entries from 679543 files; Home said `43 maps · 947 vehicles`.
