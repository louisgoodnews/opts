## 🎯 Objective

Fix the library, not the screens: states and focus in every widget, one theme, UI scale, tokens that are actually applied, an action layer and a way to test the UI by id. Every later milestone depends on it.

## 📦 Deliverables & Tasks

### Phase A: Specification and spikes
- [ ] Revise [`gui-design-system.md`](../../architecture/gui-design-system.md) to the real token set (34 roles, shadows, density, status roles, instrument tokens) and the layer model of [expandability §2](expandability.md#2-layers-and-crates). *Token set done 2026-10-12 (46 roles, generated tables); the layer-model section is open (part B).*
- [x] Spikes with a written verdict: text input with IME and paste; accessibility tree support in Bevy 0.20; a virtualised list ([`ui-spikes.md`](../../architecture/ui-spikes.md), part B, 2026-10-12). *Open (part A):* rendered comparison of 2–3 typefaces (decision D-UI-03). The rendered typeface comparison was done by part A (Noto Sans, decision D-UI-03).

### Phase B: Tokens and theme
- [x] Typography: chosen family (Noto Sans: three distinct bundled weights, 600 renders as 700; tabular figures; upgrade path to a variable font documented) with 9 styles; line height, tracking, weight, family and tabular figures applied; nothing below 12 px (interim `MinTextSize` clamp until screens migrate).
- [x] `Dense` and `Compact` density modes; **UI scale 75–200 %** as a resource and a setting; layout classes (compact / medium / expanded); minimum window 1024×640. *(The first-run scale suggestion from the display's pixel density is open.)*
- [x] Status roles (`Success`, `Warning`, `Info`); real shadows; elevation tint in both themes; motion tokens consumed by a transition system (`BackgroundTransition`); reduced motion honoured (setting and OS hint).
- [x] **One theme everywhere**: loading screen, HUD chrome and stubs use roles; the instrument token set is separate and documented. Dark default (D-UI-02), High-contrast theme, *System* and *Auto (clock)* modes ([investigation](theme-auto-switch.md)): the pure `theme_for` function, hours settings, no switch during modal, loading or a drive.
- [x] **`NotAvailableYet` component and registry** (red "Feature not available yet!" text in one style, `NotYet{milestone}` availability, generated list, test) used by every placeholder in later milestones.
- [x] Accent presets generated with an automatic contrast guard; per-widget colour overrides removed (D-UI-05); a contrast test over every theme and preset (89 pairs × 3 themes × 5 presets); RON theme files with the same checker.

### Phase C: Widgets
- [x] Hover, focus (ring), pressed, selected, disabled-with-reason and error states in **every** widget, defined once as state layers; pointer activation on release with cancel. *(Part B: `interaction::layer`, `interaction::activation`; the disabled container is approximated by a scrim, see [`gui-design-system.md`](../../architecture/gui-interaction-layer.md).)*
- [x] Keyboard operability for notebook tabs, tree view, combobox, switches and toasts; a working `TextField`; arrow navigation and landmarks in the focus system; tab order from layout, not `tab_index`. *(Tab order = layout-tree order; arrows use geometry.)*
- [x] Action layer (`UiAction`) mapping keyboard and gamepad; the existing menu hover/focus/Enter systems move into the library.
- [ ] Single bundle-returning builders (no `spawn` / `spawn_child` duplicates). *Done in part B:* migration off the deprecated `Interaction` to `Hovered`/`Pressed` and removal of the crate-wide `#![allow(deprecated)]`; the builders still have both spawn forms.

### Phase D: Testability and localisation scaffold
- [x] Stable UI ids and the control-protocol commands `ui.tree`, `ui.click`, `ui.focus`, `ui.action`, `ui.state` (documented in the control-protocol page).
- [x] CI rules from [expandability §7](expandability.md#7-testing): minimum target size, keyboard traversal, no hard-coded colours/strings, text size, disabled-with-reason (`opts_gui::testing::rules`; tests `crates/opts-gui/tests/ci_rules.rs`, `crates/opts-game/tests/ui_rules.rs`). *Open (part A):* contrast over resolved backgrounds. *(status sync 2026-10-25: done by M-0065: the rendered-tree contrast rule `opts_gui::testing::rules::text_contrast` (`a6b98f15`, 2026-10-12).)*
- [x] Fluent-based string tables with English and German skeletons and the pseudo-locale; the first screens use keys. *(Own Fluent-subset parser: no Fluent crate in the offline registry; the main menu and the library use keys.)*
- [x] Component gallery example covering every component in every state (`cargo run -p opts-gui --example gallery`).

## ✅ Acceptance Criteria
- A scripted traversal reaches and activates every interactive element of the gallery by keyboard alone.
- No interactive target below 32×32 and no text below 12 px in the gallery and in the existing screens (or a recorded exception).
- All themes and accent presets pass the contrast test; no hard-coded colour outside the token files and the instrument set.
- The game still starts, loads and drives at every commit.
