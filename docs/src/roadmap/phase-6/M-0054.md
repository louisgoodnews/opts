# ⚙️ M-0054: `opts-script_engine` — the script runtime as a crate

| Metadata | Value |
| :--- | :--- |

Extract the script runtime from `opts-sim` (`script/` lexer, compiler, VM, strings, variables, vehicle loader, host interface) into its own Bevy-free crate and add the headless rig. `opts-sim` re-exports it, so the game and the VM corpus examples keep working.

- [ ] New crate `opts-script_engine` in the workspace; move `opts_sim::script` (history kept); `opts_sim::script` becomes a re-export.
- [ ] Headless **rig**: scripted world (pedal profile, speed, per-wheel speeds, time step), recorded outputs as CSV/JSON, assertions API (VS0 of the [script route](../../architecture/vehicle-scripts-route.md)).
- [ ] Corpus examples (`osc_corpus`, `osc_bench`, `vehicle_scripts`) move with the crate; numbers unchanged (6,062 files, 0 errors).
- [ ] Build API for generated scripts: a small typed builder (blocks, macros, `if` trees) that prints compilable `.osc` text and round-trips through the compiler.
- [ ] Docs: update [script VM](../../architecture/script-vm.md), crate graph.

**Acceptance:** `cargo test -p opts-script_engine` green; the game plays unchanged; the rig reproduces the golden outputs of three reference vehicles.
