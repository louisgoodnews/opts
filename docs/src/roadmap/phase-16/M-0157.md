## 🎯 Objective

Decide whether breakdowns belong in OPTS. If they do, add one failure class with a repair action, behind a setting that is off by default.

## 🧩 Scope

1. **Decision memo** (first, no code): the scope, the failure classes, whether the OMSI option values are known (the options dialogue is not in the corpus), and what the driving loop gains and loses.
2. If approved: one failure class (electrics or doors) driven by the vehicle's failure variables, with the setting off by default.
3. A repair action at a depot, cleared by the same variables.

## ✅ Acceptance Criteria

1. The decision is recorded in a design page, with the owner's answer.
2. If approved: a test shows the failure state and that repair clears it; the setting default is Off.
3. A dated in-game check of one failure and one repair.

## ⚠️ Risks

- Large, and it reshapes the driving loop. Keep the first slice to one class.
- Event-raised triggers (`E7`) are deferred; the first slice must not depend on them.
