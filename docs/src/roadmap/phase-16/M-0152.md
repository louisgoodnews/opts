## 🎯 Objective

A free drive has no trip, so `admits()` finds no matching destination pair (`crates/opts-sim/src/passengers/destination.rs:88`) and a bus with no timetable run has destination `None` (`crates/opts-game/src/passengers/destinations.rs:56-60`). The default drive therefore takes no passenger on at any stop. Choose one rule, implement it, and test it.

## 🧩 Scope

1. Owner decision, recorded in [Passengers](../../simulation/passengers.md) §2: **(a)** a free drive boards people whose destination the stop serves; or **(b)** a free drive takes a default trip for the stop's line. Recommended: (a), because it needs no new setting.
2. Implement the chosen rule in `opts-sim` and `opts-game`.
3. Boarding test with `bus = None` at a served stop. It must fail when the rule is removed.
4. Until the rule is done, the M-0101 card states the limit (done with the 2026-11-18 board update).

## ✅ Acceptance Criteria

1. The rule is written in passengers.md §2 and linked from the wizard's trip step.
2. A boarding test with a free drive exists and fails on the parent commit (Definition of Done rule, ISS-022).
3. Dated in-game check: a free drive at one timetabled stop boards the people the stop shows. **Open** (the game was not run on 2026-11-22).
4. ISS-036 is closed in the issue register with the commit that closes it.

## ⚠️ Risks

- Boarding everyone at every stop may overfill a bus; capacity limits of the density baselines and M-0124 apply.
- Option (b) changes the wizard default and the "No trip" wording.

## 📝 Notes

No code before the owner decision. Rule (a) is implemented in `admits` (`opts-sim`); rule (b) is not taken. A bus with a chosen trip keeps the pair rule. The `bus = None` tests are: the `admits` unit test (`a_free_drive_boards_a_passenger_whose_destination_the_stop_serves`), and two boarding-path tests in `crates/opts-game/src/passengers/system/board/tests.rs` (`a_free_drive_boards_an_unseen_passenger_whose_destination_the_stop_serves` through `board_unseen`, `a_free_drive_boards_a_walking_passenger_whose_destination_the_stop_serves` through `walk_to_doors`). Both use in-code fixtures and need no game data. With the free-drive arm set to false, all fail; restored, they pass. Acceptance 2 is checked by that removal run, since the parent commit has no such test. A third test, `update_passengers_boards_a_free_drive_passenger_whose_destination_the_stop_serves` in `crates/opts-game/src/passengers/system/board/system_tests.rs`, runs the whole `update_passengers` system (bus with no route, `bus = None`) and checks the served person boards and the unserved one stays. With the free-drive arm set to false it fails (`the served person boards through the open entry`); restored, it passes. Commit 7960b323 on `agent/passengers-system`.
