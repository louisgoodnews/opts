## 🎯 Objective

Implement strongly typed, pure Rust parsers in `opts-core` for vehicle configuration manifests (`.bus`), passenger internal path routing files (`paths.cfg`), vehicle registration and fleet number pools (`.org`), and currency systems (`Money/<pack>/*.cfg`). This milestone provides the complete vehicle initialization data model required by `opts-sim` to spawn buses, seat passengers, draw randomized license plates, and process fare transactions.

---

## 🔍 Scope

**In Scope:**
- Module `opts_core::formats::vehicles::bus` parsing top-level `.bus` blocks (`[friendlyname]`, `[description]`, `[number]`, `[registration_list]`, `[sound]`, `[paths]`, `[passengercabin]`, `[scripts]`, `[varnamelist]`, `[constfile]`, etc.).
- Module `opts_core::formats::vehicles::paths` parsing passenger waypoint networks, entry/exit door assignments, seat links, and standing positions from `paths.cfg`.
- Module `opts_core::formats::org` parsing registration pools, list frequencies, repetition weights, and randomized selection state.
- Module `opts_core::formats::money` parsing currency packs (`[currency]`, `[coin]`, `[bill]`) and denomination values.
- Shared text parser combinators utilizing `nom`.
- Unit tests with synthetic test files for all 4 format parsers.
- Corpus validation tests verifying tolerance against real-world file variances (trailing comments, whitespace differences, encoding fallbacks).
- Module-level and item-level rustdoc documentation.

**Out of Scope:**
- Runtime bus physics or vehicle powertrain simulation (belongs in `opts-sim`).
- Passenger AI pathfinding execution (belongs in `opts-sim`).
- Audio playback or script execution (belongs in `opts-sim` / `opts-script`).
- Rendering 3D mesh attachments from model configs (belongs in `opts-bevy`).

## 📦 Deliverables & Tasks

### 🔲 Vehicle Manifest Parser (`.bus`)
- [ ] Define `BusSpec` data structure capturing metadata, asset references, and script linkages.
- [ ] Implement `nom` keyword parsers for standard vehicle declaration blocks.
- [ ] Parse registration mode precedence (`[number]`, `[registration_list]`, `[registration_automatic]`, `[registration_free]`).
- [ ] Implement lenient fallback for optional or variable-count description blocks.

### 🔲 Passenger Paths Parser (`paths.cfg`)
- [ ] Define `PassengerPaths` data structure (`PathPoint`, `PathLink`, `DoorEntry`, `DoorExit`).
- [ ] Parse `[pathpoint]` coordinates, direction vectors, height, and seat/walk attributes.
- [ ] Parse `[pathlink]` connections between pathpoints.
- [ ] Parse `[entry]` and `[exit]` door bindings.

### 🔲 Registration & Fleet Number Parser (`.org`)
- [ ] Define `RegistrationPool` structure.
- [ ] Parse newline-delimited free-text lists.
- [ ] Implement repetition frequency weighting and non-consuming randomized selection helper.
- [ ] Support large registration files and single-entry variants observed in the corpus.

### 🔲 Money System Parser (`Money/*.cfg`)
- [ ] Define `MoneySystem` structure with currency identifier, decimals, coins, and bills.
- [ ] Parse `[currency]` declaration block.
- [ ] Parse `[coin]` mesh filename and decimal value.
- [ ] Parse `[bill]` mesh filename and decimal value.

### 🧪 Tests & Quality Assurance
- [ ] Unit tests for each parser covering standard syntax and edge cases.
- [ ] Corpus-based integration tests verifying robust parsing on non-empty files.
- [ ] Zero `unsafe` blocks, zero `unwrap()`, strict `thiserror` error handling.

## ✅ Acceptance Criteria (Definition of Done)

1. `cargo test -p opts-core` passes all unit tests for `.bus`, `paths.cfg`, `.org`, and `money.cfg`.
2. All parsers return descriptive typed errors on malformed syntax without panicking.
3. Decodes sample `DM.cfg` and Euro packs into valid `MoneySystem` structures.
4. Correctly evaluates weighting on repeated `.org` entries (e.g. `E1_1.org`).
5. `cargo clippy -- -D warnings` and `cargo fmt --check` pass cleanly.
6. Documentation adheres to `docs/src/contributing/standards.md`.

## ⚠️ Risks & Mitigations

| Risk | Likelihood | Impact | Mitigation |
| :--- | :---: | :---: | :--- |
| **Irregular whitespace and comment banners polluting parameter lines.** | Medium | Medium | Implement standard line-normalizing tokenizer stripping comments (`#`, `//`, `---`) before block parsing. |
| **Mixed encoding in `.org` files (CP1252 vs UTF-8).** | Low | Low | Apply standard lenient decoding (UTF-8 with CP1252 fallback) established in documentation standards. |
| **Float formatting variance in denomination values (`0.1` vs `0.10`).** | Low | Low | Parse denomination values directly to `f64` per resolution in `money.md`. |

## 📋 Implementation Plan

1. Implement `opts_core::formats::org` (simplest line format).
2. Implement `opts_core::formats::money` (straightforward keyword format).
3. Implement `opts_core::formats::vehicles::paths` (`paths.cfg` waypoint network).
4. Implement `opts_core::formats::vehicles::bus` (`.bus` configuration manifest).
5. Comprehensive unit test suite and integration validation.
