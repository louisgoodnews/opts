## 🎯 Objective

Implement a robust, safe, pure Rust parser in `opts-core` (`opts_core::formats::x`) for Microsoft DirectX `.x` mesh files (`xof 0303txt 0032` and `xof 0302txt`). The parser transforms raw `.x` text buffers into structured in-memory meshes (`XMesh`) containing verified 3D vertex streams (positions, normals, UVs), face index buffers with native triangle and CCW quad triangulation, material definitions (both inline and resolved by named references), and frame transformation matrices.

---

## 🔍 Scope

**In Scope:**
- Module `opts_core::formats::x` and submodules (`error`, `header`, `lexer`, `triangulate`, `ast`, `parse`).
- 16-byte header validation (`xof 0303txt 0032`, `xof 0302txt 0032`, `xof 0302txt 0064`), gracefully rejecting unsupported binary variants (`bin `).
- Streaming tokenizer handling `#` and `//` comments, flexible `,` and `;` punctuation, identifiers, strings, and numeric literals.
- Template skipping for exporter boilerplate (`template ...`, `DeclData`, `FVFData`, `ObjectMatrixComment`).
- Essential block parsing: `Mesh`, `MeshNormals`, `MeshTextureCoords`, `MeshMaterialList`, `Material`, `TextureFilename`, `Frame`, `FrameTransformMatrix`.
- Quad triangulation: splitting 4-vertex quad faces `(i0, i1, i2, i3)` into triangles `(i0, i1, i2)` and `(i0, i2, i3)` preserving CCW front-facing winding.
- Named material reference resolution: resolving `{ MaterialName }` inside `MeshMaterialList` to defined top-level `Material` blocks.
- Unit tests using synthetic `.x` snippets.
- Integration tests against all 7 clean-room mutation fixtures (`t10_x_ident_quad.x`, `t10_x_ident_tri.x`, `t11_x_scale0025.x`, `t11_x_swapyz.x`, `t11_x_translate3.x`, `t12_x_refmaterial.x`, `t12_x_reversed.x`).
- Robustness and pseudorandom fuzz tests confirming zero panics on malformed or truncated inputs.
- Crate-level and module-level rustdoc documentation.

**Out of Scope:**
- Binary `.x` token stream decoding (`bin ` is rare in OMSI: 26 of 8,145 files; cleanly rejected with `Err`).
- Skeletal animation / skinning deformation (`XSkinMeshHeader`, `SkinWeights`).
- Direct GPU mesh creation or Bevy rendering logic (deferred to `opts-bevy`).
- Texture image decoding (`.bmp`, `.tga`, `.dds`) (deferred to `opts-assets`).
- File I/O inside `opts-core` (parsers accept byte slices `&[u8]`).

## ⚠️ Risks & Mitigations

| Risk | Likelihood | Impact | Mitigation |
| :--- | :---: | :---: | :--- |
| **Inconsistent punctuation across exporters (`,,`, `;`, `;;`).** | High | Medium | Rely strictly on declared counts (`nVertices`, `nFaces`) rather than punctuation boundaries; treat `,` and `;` as generic separators. |
| **Named material forward references (defined after mesh).** | Low | Medium | Two-pass material resolution: gather top-level materials and inline materials into a registry before resolving references. |
| **Quadrilateral triangulation winding reversal.** | Low | High | Enforce standard CCW order: quad `(0, 1, 2, 3)` splits into `(0, 1, 2)` and `(0, 2, 3)`. Verified against mutation test T10 in OMSI. |
| **Binary `.x` files passed into parser.** | Low | Low | Check header format field; immediately return explicit `Err(XParseError::UnsupportedFormat("bin"))` instead of cryptic syntax errors. |
