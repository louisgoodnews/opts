## 🎯 Objective

Design and implement a dynamic map chunk paging and spatial streaming engine capable of loading, instantiating, and unloading adjacent OMSI map tiles (`tile_*.map`) and scenery splines around the active player vehicle. Establish a grid streaming coordinator in `opts-game` that monitors player coordinates, predicts tile boundary crossings, loads adjacent scenery asynchronously via Bevy's `AsyncComputeTaskPool`, and unloads distant entities to maintain memory budgets and 60 FPS frame times.

---

## 🔍 Scope

**In Scope:**
- **Phase A — Architecture Specification:**
  - Author `docs/src/architecture/map-streaming.md` detailing grid indexing, tile load radius, priority queues, and coordinate offset transformations.
  - Define entity life-cycle states (`Pending`, `Loading`, `Active`, `Culled`, `Evicted`).
- **Phase B — Streaming Core & ECS Systems (`opts-bevy`, `opts-game`):**
  - Implement `TileGridManager` resource tracking active tile coordinate pairs `(x, y)` in OMSI grid space.
  - Implement `tile_streaming_system` running in `Update` schedule that calculates Euclidean distance to tile centers and triggers async load/unload tasks.
  - Implement spatial entity parent hierarchy (`TileEntityBundle`) allowing atomic despawning of an entire unloaded tile's scenery objects, spline meshes, and terrain nodes.
  - Handle background texture and mesh asset prefetching for adjacent tiles.
- **Phase C — Validation & Headless Integration Testing:**
  - Headless streaming tests simulating vehicle translation across tile borders and verifying chunk eviction without memory leaks.
  - Interactive demonstration scene loading multi-tile route chunks with debug visualization bounding boxes.

**Out of Scope:**
- Terrain heightmap mesh tessellation and water vertex deformation (covered separately in M-0025).
- Traffic AI route pathfinding and timetable dispatch (scheduled in subsequent transit milestones).
