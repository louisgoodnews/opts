## 🎯 Objective

Move tile, terrain, spline, object, sky and text-texture loading from `opts-game/src/in_game/omsi_world/` into `opts-bevy` behind a plugin, so it can be tested headlessly and reused by tools, and cut the `opts-bevy` → `opts-gui` dependency by moving the reporting modal.

---

## 📦 Deliverables & Tasks

### 🔲 Phase A: Plan
- [ ] Interface between `WorldLoadJob` (game session: map choice, entry point, vehicle) and the loader (tiles, caches, decode pool); list of `opts-game` types that must move.

### 🔲 Phase B: Refactor
- [ ] Move modules one at a time (`ground`, `tile_ground`, `tile`, `trees`, `job`); keep the control and hot-reload hooks working.
- [ ] Move AI traffic (`omsi_world/traffic.rs`), pedestrians (`pedestrians.rs`), articulated-segment spawning and bellows skinning (`vehicle.rs`) and repaint discovery (`new_game_screen/repaints.rs`, called from the world loader) along with the loader ([critical review 2026-10-11](../../meta/critical-review-2026-10-11.md) F-009).
- [ ] Move the reporting modal UI to `opts-game` (or an `opts-reporting-ui` module) and drop the `opts-gui` dependency from `opts-bevy`.

### 🔲 Phase C: Verification
- [ ] Headless integration test loading a synthetic map (tile + terrain + sco) through the plugin; screenshots of three maps unchanged.

---

## 📝 Notes

Pure refactor; behaviour must not change. Pre-condition for the Bevy upgrade (M-0044) being tractable: fewer crates touch Bevy's UI and scene APIs.
