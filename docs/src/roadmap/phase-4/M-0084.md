## 🎯 Objective

In the driver's view (camera 4) the user can open a **viewpoint editor with the Tab key** and adjust the eye position (X, Y, Z, i.e. height and placement) and the **field of view**; the result is **saved per vehicle** and loaded as the default for that view on that vehicle.

## 📦 Deliverables & Tasks
- [x] Docs first: the driver's view is **key 2 (Cockpit)**, `[add_camera_driver]` presets, label `Driver's view x/n`; specified in [camera system](../../architecture/camera-system.md#viewpoint-editor-drivers-view-key-2--m-0084).
- [x] **Editor mode (Tab):** only while the driver's view is active (and later other interior views); Tab toggles; pauses nothing; a compact panel in the HUD style ([HUD registry](../../architecture/hud-registry.md), no focus theft except while editing): sliders and number fields for X, Y, Z offsets (cm precision, sane limits) and FOV (30–120°), *Reset to vehicle default*, *Save*, *Cancel*; keyboard and mouse operation, live preview in the 3D view; reversible (Esc cancels). Implemented as +-0.6 m offsets from the vehicle's eye (X, Y, Z, 1 cm steps) and FOV 30-120; keyboard (arrows, Shift x10, Home, Enter/Tab save, Esc cancel) and mouse (buttons, clickable track).
- [x] **Per-vehicle storage:** keyed by the vehicle's catalogue identity (and optionally repaint-independent), versioned file in the user data directory (JSON, section of the future session save); loaded when the vehicle is spawned and when the view is entered; falls back to the vehicle-defined viewpoint; validation of corrupt entries. `viewpoints.json` beside `drive_history.json`, key = `.bus` stem, per driver camera.
- [~] Apply to all vehicles of the same model, with a per-vehicle override; export/import of viewpoints for sharing. *(open)* *(status sync 2026-10-25: model-wide viewpoints with a per-vehicle override exist (`SaveModel`, `scope_model` in `crates/opts-bevy/src/camera/viewpoint.rs`, `abe70bda`, 2026-10-13); export/import not found.)*
- [x] Control protocol: `camera.viewpoint.get/set/save/reset` done; the default-FOV setting is open. *(status sync 2026-10-25: `graphics.default_fov` (0 = vehicle's own, up to 120°) is registered in `crates/opts-game/src/settings_registry/builtin/graphics.rs` since `abe70bda`.)*
- [x] Help overlay and controls registry list Tab; input gating audit updated.
- [x] Tests: edit → save → respawn → loaded; per-vehicle isolation; limits; reset.

- [x] *(status sync 2026-10-25: `opts_bevy::camera::reset::reset_view` (default per view, the cockpit's stored viewpoint), Shift + Space in the Help controls, `camera.reset` — `f7df4cef`, 2026-10-13.)* **Default position per view and reset (R-33):** every camera view has a default position/orientation (the vehicle-defined one, or the saved viewpoint of M-0084); **Shift + Space** resets the current view to it (today it resets the camera generally); documented in the Help controls registry and covered by a test per view kind.

## ✅ Acceptance Criteria
- On two different vehicles the driver's view can be set differently; after restarting the game each vehicle starts with its own saved viewpoint; Tab opens and closes the editor; FOV changes are visible live.
