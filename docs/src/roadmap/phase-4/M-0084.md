## 🎯 Objective

In the driver's view (camera 4) the user can open a **viewpoint editor with the Tab key** and adjust the eye position (X, Y, Z, i.e. height and placement) and the **field of view**; the result is **saved per vehicle** and loaded as the default for that view on that vehicle.

## 📦 Deliverables & Tasks
- [ ] Docs first: how the driver's-view camera position is defined today (`[camera]`/`[viewpoint]` in the vehicle files, camera index numbering, default FOV); what the in-game label shows (the camera label reads 'x/n'); write the spec in the camera-system page.
- [ ] **Editor mode (Tab):** only while the driver's view is active (and later other interior views); Tab toggles; pauses nothing; a compact panel in the HUD style ([HUD registry](../../architecture/hud-registry.md), no focus theft except while editing): sliders and number fields for X, Y, Z offsets (cm precision, sane limits) and FOV (30–120°), *Reset to vehicle default*, *Save*, *Cancel*; keyboard and mouse operation, live preview in the 3D view; reversible (Esc cancels).
- [ ] **Per-vehicle storage:** keyed by the vehicle's catalogue identity (and optionally repaint-independent), versioned file in the user data directory (JSON, section of the future session save); loaded when the vehicle is spawned and when the view is entered; falls back to the vehicle-defined viewpoint; validation of corrupt entries.
- [ ] Apply to all vehicles of the same model, with a per-vehicle override; export/import of viewpoints for sharing.
- [ ] Control protocol: `camera.viewpoint.get/set/save/reset`; settings for default FOV.
- [ ] Help overlay and controls registry list Tab; input gating audit updated.
- [ ] Tests: edit → save → respawn → loaded; per-vehicle isolation; limits; reset.

## ✅ Acceptance Criteria
- On two different vehicles the driver's view can be set differently; after restarting the game each vehicle starts with its own saved viewpoint; Tab opens and closes the editor; FOV changes are visible live.
