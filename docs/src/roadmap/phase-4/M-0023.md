## 🎯 Objective

Bridge the pure Rust vehicle dynamics core from `opts-sim` into Bevy's ECS architecture within `opts-bevy`. Implement components and systems running in Bevy's `FixedUpdate` schedule that step vehicle physics deterministically, map driver input devices (keyboard/gamepad) to `VehicleInputs`, synchronize vehicle 2D chassis positions and yaw headings to 3D Bevy `Transform` components via `OptsCoordsPlugin`, and animate child wheel mesh transforms for realistic steering angles and wheel rotation. Deliver an interactive, runnable driving example (`crates/opts-bevy/examples/drive_bus.rs`) with exterior chase and interior cabin cameras.

---

## 🔍 Scope

**In Scope:**
- **Phase A — Architecture Specification:**
  - Author `docs/src/architecture/vehicle-ecs-bridge.md` defining the ECS bridge pattern between pure simulation state (`opts-sim`) and rendering entities (`opts-bevy`), fixed-timestep scheduling (`FixedUpdate`), input mapping, and wheel hierarchy animation.
  - Update `docs/src/SUMMARY.md` to index the new architecture chapter.
- **Phase B — Crate Implementation (`crates/opts-bevy`):**
  - Implement ECS Components:
    - `VehicleController`: Component wrapping `opts_sim::VehicleSimulation`.
    - `PlayerVehicle`: Marker component denoting the vehicle accepting player inputs.
    - `WheelVisual`: Component identifying wheel sub-entities with axle index and wheel side (Left/Right) for dynamic rotation and steering transforms.
    - `VehicleCameraRig`: Component for smooth exterior orbit/chase camera and interior driver viewpoints.
  - Implement ECS Systems:
    - `vehicle_input_system`: Maps player keyboard/gamepad axes (`W`/`S` throttle/brake, `A`/`D` steering, `Space` handbrake, `D`/`N`/`R` gear selector) to `VehicleInputs`.
    - `vehicle_physics_step_system`: Runs in `FixedUpdate` (60 Hz) stepping `VehicleSimulation::step(dt)`.
    - `vehicle_transform_sync_system`: Synchronizes 2D simulation coordinates to 3D Bevy `Transform` using `omsi_to_bevy_pos`.
    - `wheel_transform_sync_system`: Updates local rotation of child wheel entities for steering yaw and rolling spin.
    - `vehicle_camera_system`: Manages camera chase tracking and cockpit viewpoint positioning.
  - Register all components and systems via `OptsVehiclePlugin` and unified `OptsAssetPlugin`.
- **Phase C — Interactive Example & Verification:**
  - Build runnable interactive application `crates/opts-bevy/examples/drive_bus.rs` featuring a drivable bus model, asphalt ground plane, camera view toggling (`F1` chase / `F2` cockpit), and on-screen telemetry overlay (speedometer, RPM, gear, steering lock).
  - Headless integration tests in `crates/opts-bevy/tests/vehicle_sim_sync.rs` verifying transform sync and wheel rotation.
  - Update `docs/crates/opts-bevy.md` and `docs/crates/opts-bevy/README.md`.

**Out of Scope:**
- Full OMSI world tile streaming or terrain mesh collisions (uses flat ground plane; full world streaming is in subsequent tile loading milestone).
- OMSI bytecode script VM execution (`.osc` script evaluation).
- Passenger boarding / alighting logic.

## ⚠️ Risks & Mitigations

| Risk | Impact | Mitigation |
| :--- | :--- | :--- |
| **Physics / rendering visual jitter between ticks** | Medium | Execute `VehicleSimulation::step` strictly within Bevy's `FixedUpdate` schedule, using smooth transform propagation. |
| **Coordinate inversion between Bevy Y-up and vehicle space** | High | Utilize canonical spatial conversion functions in `opts_bevy::coords` (`omsi_to_bevy_pos`, `bevy_quat_to_omsi_euler`) proven in M-0020. |
| **Missing wheel entities in vehicle models** | Low | Provide fallback root-only movement if child wheel meshes are not tagged with `WheelVisual`. |
