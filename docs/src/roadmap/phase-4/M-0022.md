## 🎯 Objective

Design and implement the deterministic vehicle physics and kinematics core in `opts-sim` with zero Bevy dependencies. Build a robust simulation engine for multi-axle commercial road vehicles (rigid transit buses and multi-unit articulated vehicles) driven by parsed `BusManifest` and `BusAxle` specifications from `opts-core`. Implement multi-axle Ackermann steering geometry, longitudinal powertrain propulsion and multi-stage braking models, normal force tire-ground interactions, chassis inertial state integration, and suspension spring-damper compliance, fully specified in `docs/src/simulation/vehicle_physics.md` under Documentation-Driven Development.

---

## 🔍 Scope

**In Scope:**
- **Phase A — Mathematical & Physical Specification:**
  - Author `docs/src/simulation/vehicle_physics.md` defining vehicle coordinate frames, Ackermann steering geometry for arbitrary axle placements, longitudinal drive torque / braking deceleration curves, rolling resistance, aerodynamic drag, lateral tire slip compliance, static/dynamic load transfer, and articulation joint constraints.
  - Update `docs/src/SUMMARY.md` to index the new physics architecture chapter.
- **Phase B — Crate Architecture & Simulation Engine (`crates/opts-sim`):**
  - Implement vehicle input state: `VehicleInputs` (analog steering, throttle, service brake, retarder, handbrake, gear selector).
  - Implement axle and wheel kinematics: `AxleState`, `WheelState`, Ackermann angle calculations per axle, wheel rotational velocity, and rolling radii based on `BusAxle` parameters.
  - Implement chassis rigid body state: `ChassisState` (position, heading, linear velocity, angular yaw velocity, mass distribution from `mass_tonnes`).
  - Implement longitudinal powertrain & braking dynamics: engine torque transmission, gear ratios, retarder stages, mechanical friction brakes, and aerodynamic drag ($F_{drag} = \frac{1}{2} \rho C_d A v^2$).
  - Implement vertical suspension compliance: suspension deflection, spring-damper force calculation, and dynamic pitch/roll load transfer.
  - Implement articulated chassis coupling kinematics: pitch/yaw constraint solver connecting tractor and trailer units via `coupling_front_y` / `coupling_back_y`.
  - Implement fixed-step numerical integration engine (`VehicleSimulation::step(&mut self, dt: f32)`) ensuring determinism and stability across variable simulation frequencies.
- **Phase C — Testing & Documentation:**
  - Unit tests covering steering geometry, acceleration profiles, stopping distances, and numerical stability.
  - Integration tests verifying realistic physics reproduction against canonical OMSI bus data (e.g. standard 12m two-axle low-floor bus).
  - Crate documentation in `docs/crates/opts-sim.md` and `docs/crates/opts-sim/README.md`.

**Out of Scope:**
- Bevy ECS component wrappers or rendering systems (scheduled for subsequent Phase 4 milestone bridging `opts-sim` to `opts-bevy`).
- OMSI bytecode script VM execution (`.osc` script evaluation; handled in vehicle scripting milestone).
- Full 3D triangular mesh collision geometry (uses 2D planar / heightfield elevation abstraction).
- AI pathfinding and traffic behavior (covered in passenger and AI traffic milestones).

## ⚠️ Risks & Mitigations

| Risk | Impact | Mitigation |
| :--- | :--- | :--- |
| **Numerical instability at low speeds or large $dt$** | High | Employ semi-implicit Euler integration with velocity epsilon clamping ($\le 10^{-4}\text{ m/s}$) to eliminate low-speed jitter. |
| **Over-coupling to Bevy engine types** | High | Enforce strict isolation: `opts-sim` depends only on `opts-core`, `glam`, and standard Rust primitives; zero Bevy imports allowed in `opts-sim`. |
| **Incomplete bus parameter data from manifests** | Medium | Provide physically realistic fallback defaults for optional manifest fields (`spring_rate`, `damping`, `max_force`, `wheel_diameter`). |
| **Complex articulation jackknifing singularities** | Medium | Bound articulation joint angle within safe mechanical limits ($\pm 54^\circ$) and apply angular damping torque near extremes. |

## 📋 Implementation Plan

### 1. Preconditions
- Phase 2 parsers (`opts-core`) are complete; `BusManifest` and `BusAxle` data structures are available.
- `opts-sim` crate exists in the Cargo workspace with math dependencies (`glam = "0.27"`, `thiserror`, `serde`).
- The project documentation pipeline (`mdBook`) is functional.

### 2. Sequence of Steps
1. **Spec Creation:** Write `docs/src/simulation/vehicle_physics.md` documenting coordinate definitions, kinematics equations, drivetrain torque flow, and tire friction. Link into `docs/src/SUMMARY.md`.
2. **Inputs Module:** Implement `VehicleInputs` in `crates/opts-sim/src/vehicle/inputs.rs` with builder/setter helpers for analog axis controls (steering $[-1.0, 1.0]$, throttle $[0.0, 1.0]$, brakes $[0.0, 1.0]$, gear selection).
3. **Axle & Wheel Module:** Implement `AxleState` and `WheelState` in `crates/opts-sim/src/vehicle/axle.rs`. Implement dynamic Ackermann angle derivation ($\delta_i = \arctan\left(\frac{L}{R \mp W/2}\right)$) based on wheelbase and steering input.
4. **Suspension Module:** Implement spring-damper compliance and dynamic load transfer in `crates/opts-sim/src/vehicle/suspension.rs`.
5. **Drivetrain & Brake Module:** Implement torque calculation and brake force in `crates/opts-sim/src/vehicle/drivetrain.rs`.
6. **Articulation Module:** Implement `ArticulationJoint` in `crates/opts-sim/src/vehicle/articulation.rs` for multi-section vehicles.
7. **Chassis Dynamics & Simulation Controller:** Implement `ChassisState` and `VehicleSimulation` in `crates/opts-sim/src/vehicle/chassis.rs` and `mod.rs`. Provide builder from `&BusManifest`.
8. **Root Integration & Crate Lints:** Expose APIs in `crates/opts-sim/src/lib.rs` with `#![deny(unsafe_code)]` and `#![warn(missing_docs)]`.
9. **Tests:** Implement unit tests in each submodule and end-to-end integration tests in `crates/opts-sim/tests/vehicle_kinematics.rs`.
10. **Crate Documentation:** Author `docs/crates/opts-sim.md` and `docs/crates/opts-sim/README.md`.
