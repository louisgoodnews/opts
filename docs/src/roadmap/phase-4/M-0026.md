## 🎯 Objective

Design and implement a deterministic, high-performance, pure Rust execution engine for OMSI vehicle and scenery scripts (`.osc`). Provide a reverse-Polish notation (RPN) stack virtual machine capable of compiling `.osc` token streams into bytecode, maintaining dynamic numeric/string variable tables (`varnamelist.txt`, `stringvarnamelist.txt`), evaluating constant tables (`constfile.txt`), and invoking standard simulation lifecycle callbacks (`{init}`, `{frame}`, `{trigger}`) on each simulation tick. This milestone resolves the critical architectural blocker preventing authentic OMSI bus behavior.

---

## 🔍 Scope

**In Scope:**
- **Phase A — Architecture Specification:**
  - Author `docs/src/architecture/script-vm.md` documenting stack execution semantics, bytecode instruction set, variable scope, system macro bindings, and numeric precision rules.
  - Index the new specification in `docs/src/SUMMARY.md`.
- **Phase B — VM Core & Compiler (`crates/opts-sim`):**
  - Implement `.osc` Lexer and Bytecode Compiler: Converts RPN script text into structured `OpCode` sequences (stack pushes, arithmetic, logical comparisons, branching `if`/`else`/`endif`, macro invocations).
  - Implement `ScriptVm`: A stack-based execution machine with operand stack, local call frame, and time delta integration.
  - Implement `VariableTable`: Fast indexed numeric (`f32`/`f64`) and string variable storage with string interning and name hashing.
  - Implement Macro Dispatch: Support for user-defined `{macro:...}` definitions and system callbacks.
  - Implement Core Math & Logic Builtins: Standard OMSI math operators (`+`, `-`, `*`, `/`, `min`, `max`, `exp`, `sqrt`, `random`, `sgn`, `trunc`).
- **Phase C — Testing & Verification:**
  - Comprehensive unit test suite executing verified OMSI community scripts (e.g., door control logic, transmission selector, odometer accumulation).
  - Benchmark suite in `opts-benchmark` measuring VM execution latency (target: <50 microseconds per script set per vehicle frame).

**Out of Scope:**
- Graphical script debugging GUI (deferred to Phase 5 developer tools).
- Direct Bevy ECS entity mutation from scripts (script VM remains pure Rust in `opts-sim`; Bevy systems bridge values via component synchronization).
