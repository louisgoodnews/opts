## 🎯 Objective

Design and implement a spatial audio simulation system in `opts-bevy` bridging parsed OMSI sound manifests (`sound.cfg`) and audio assets (`.wav`) into Bevy's audio pipeline. Evaluate dynamic sound parameters on each simulation tick (engine RPM pitch curves, load-dependent volume modulation, road contact rolling pitch, door actuator pneumatics, and brake squeal) and position audio emitters on vehicle sub-entities relative to the player's cockpit or chase camera listener.

---

## 🔍 Scope

**In Scope:**
- **Phase A — Architecture Specification:**
  - Author `docs/src/architecture/audio-system.md` detailing sound trigger evaluation, 2D continuous parameter curve sampling (volume vs RPM, pitch vs speed), spatial attenuation curves, and cockpit acoustic filtering.
  - Index the new specification in `docs/src/SUMMARY.md`.
- **Phase B — Sound System Implementation (`crates/opts-bevy`):**
  - Implement `SoundConfigLoader`: Load and decode `sound.cfg` configuration into audio playback definitions.
  - Implement `VehicleAudioEmitter`: Component holding active audio handles, curve lookup tables, and trigger states.
  - Implement `audio_evaluation_system`: Runs in `Update` schedule, sampling current vehicle telemetry (`engine_rpm`, `speed_mps`, `brake_pressure`) and adjusting playback volume and pitch multipliers.
  - Implement One-Shot Trigger System: Triggers discrete audio playback events for switches, door mechanisms, turn signals, and air hiss.
  - Implement `SpatialListenerBridge`: Positions Bevy's audio listener at the active driver ear position or chase camera focus.
- **Phase C — Testing & Verification:**
  - Headless unit tests verifying mathematical evaluation of piecewise linear volume and pitch curves.
  - Interactive driving example integration in `drive_bus.rs` playing dynamic engine pitch and brake release sounds.

**Out of Scope:**
- Advanced DSP environmental reverberation or impulse response modeling (scheduled for Phase 5 polish).
- Passenger crowd dialogue procedural generation.
