## 🎯 Objective

One articulation model with one state, one clock and one mass: the kinematic joint becomes part of the serialised vehicle simulation, the consist's mass acts in the longitudinal dynamics, and pitch and roll of the following units are computed in the fixed step so that every joint variable the scripts read is a function of the fixed step alone. The decision behind this scope (kinematic yaw is kept, force-based coupling is rejected, with the condition for reopening) is in the [design](../../architecture/articulation-physics.md); this file lists what is delivered and when it is done.

Test vehicle for everything below: the **MAN NG272** (the vehicle of P-1011), one articulated bus. Other articulated vehicles are covered by the fleet sweep as a no-regression check only.

## 🔍 Scope

### In scope
- Parts 1–5 below (design doc "Proposed Solution" D1–D4 and the M-0073 boundary).
- The frame-rate determinism test and its fix.
- Road articulated vehicles (buses). Trams and rail consists use the same code but are not verified for mass (Q-ART-12).

### Out of scope
- The **consist-mass aggregation** (reading each unit's `[mass]` and summing it). It is a standalone task on its own branch; this milestone consumes its output (Part 2).
- Force-based coupling, tyre side slip, hitch reaction on the head (design Q-ART-06, Q-ART-11; reopened only with data, see Risks).
- The head's own body motion (fall, rise, tilt in `follow_ground`): it stays as it is until M-0073.
- Loops and the meaning of the second `[couple_back]` line (Q-ART-13), indented keywords (Q-ART-14): recorded, not fixed here.
- Phase C deliverables of the earlier version of this milestone (below, "Carried over"), which this revision does not touch.

### Part 1 — State in `opts-sim`, serialisable (D1)
- [ ] `VehicleSimulation` holds the consist state (`TrailerKinematics` per following unit, including its previous hitch position); `ArticulationJoint` and its test are removed.
- [ ] `Serialize`/`Deserialize` for the extended state; the trailer state of a running vehicle can be saved and restored (the section list of [M-0069](../phase-10/M-0069.md) names it).
- [ ] `articulation_system` becomes a reader of the simulation; `ArticulatedSegment` keeps render-side data only.
- [ ] `VehicleSimulation::teleport(pos, heading)` re-seeds the consist; spawn and respawn call it; the jump heuristic stays as a logged safety net.
- [ ] Round-trip test: drive into a 15 m circle, serialise, restore, continue; poses and α agree with the unbroken run within 1 mm and 0.01°.

### Part 2 — Consist mass in the longitudinal dynamics (D2)
- [ ] `UnitLoad` (per unit: mass, axle positions, driven flag) is the input type; filled from the standalone task's aggregation and from `[newachse]`/`achse_antrieb` (`BusAxle::is_driven`).
- [ ] The longitudinal equation uses `Σ mass`; drive force is limited by `μ · ΣN` over the **driven** axles of all units, brake force by `μ · ΣN` over the braked axles (replacing `ROAD_FRICTION · m · g`).
- [ ] The hitch force of each joint is computed and exposed as a diagnostic value (no feedback into poses).
- [ ] The regression test of the standalone task (consist against a solo vehicle of the same total mass) passes here; no per-vehicle values in code.

### Part 3 — β/γ in the fixed step (D3)
- [ ] The per-unit part of `follow_ground` (elevation, pitch, roll of following units, `articulation_<k>_beta`/`_gamma`) is computed in `FixedUpdate` from ground heights sampled per fixed step; the head's own body motion stays in `Update`.
- [ ] The filter's time step is the fixed time step; rendering interpolates between the last two fixed poses.
- [ ] Frame-rate determinism test (the ignored test of `agent/articulation-probe`, commit `eecff08`, extended to 30, 60 and 144 frames per second): the sequences of α, β, γ per fixed step are identical.
- [ ] Before the change the failing output is recorded in the Notes; after the change the passing output.

### Part 4 — `[coupling_front_character]` mapping (D4)
- [ ] The parser already reads `max_alpha`, `min_beta`, `max_beta`, `kind` (`CouplingLimits`); verify and keep. No parser change unless the test below finds a gap.
- [ ] Runtime enforcement: `max_alpha` clamps α (kinematics), `min_beta`/`max_beta` clamp the published `articulation_<k>_beta` (sorted, since three files list them reversed), `kind` has no behavioural effect (Q-ART-04), `γ` is unlimited (Q-ART-07).
- [ ] Defaults when the block is absent or incomplete: α limit 52.5° (`spawn_trailer_chain`), β unlimited; documented in the Notes of this file.
- [ ] Test with a vehicle declaring non-default limits (a manifest fixture), and one declaring none.

## ✅ Acceptance Criteria

Parts:
1. A simulated articulated consist serialises to a byte buffer, deserialises and resumes with identical state; the save/load path in use (`M-0069`, once it exists; today the controller state in `opts-bevy`) takes the new type. No `unsafe`, no `unwrap()` in library paths.
2. An articulated consist accelerates and brakes comparably to a solo vehicle of the same total mass: **within 2 % of `a = F/Σm`** in the test harness; no per-vehicle values.
3. The frame-rate test passes at 30, 60 and 144 fps; the existing tests pass; pitch and roll on flat ground stay 0 within 0.01°.
4. A vehicle declaring limits has them enforced; one declaring none uses the documented defaults.
5. The interface to M-0073 is described in the design and referenced here.

Consolidated Definition of Done:
- All five parts pass; `cargo fmt`, `cargo clippy --all-targets -- -D warnings`, `cargo test --workspace` pass.
- **NG272, measured in the test harness** (the repository holds no OMSI reference measurements, so "matches OMSI" is not a testable criterion; the project lead's visual comparison with OMSI settles Q-ART-01/02 separately):
  - 0–50 km/h time with the unit's torque curve scales with `1/Σm` within 2 %;
  - braking distance from 50 km/h scales with `Σm` over the available friction within 2 %;
  - steady-state β on a constant slope equals the slope angle difference between the units' axle positions within 0.2°; γ is 0 on a level cross-section;
  - the trailer's mass contribution is visible: the NG272 consist reaches 50 km/h later than the head alone by the mass ratio.
- If OMSI measurements are supplied later, the same four quantities are compared with a tolerance agreed then.
- No `unsafe`, no `unwrap()` in library code; every new public item has rustdoc; every touched crate's `docs/crates/*.md` is updated.

## 📋 Implementation Plan

Steps follow the design's [implementation plan](../../architecture/articulation-physics.md#-implementation-plan); each is independently verifiable.

1. **Move the state (Part 1).** `crates/opts-sim/src/vehicle/`, `crates/opts-bevy/src/articulation.rs`. Remove `ArticulationJoint`; `articulation_system` reads the sim. Verification: `trailer::tests` and `tests/articulation.rs` pass; a new test asserts the published α equals the simulation's joint angle (design V1).
2. **Teleport (Part 1).** `opts-sim` vehicle module, spawn/respawn in `opts-game/src/in_game/omsi_world/vehicle.rs`. Verification: after `teleport` the consist hangs straight with zero wheel speed spike (regression of [chain-assembly.md](../../architecture/chain-assembly.md)).
3. **Serialisation (Part 1).** `opts-sim` vehicle module. Verification: the round-trip test (design V4).
4. **`UnitLoad` and the consist mass (Part 2).** `opts-sim` vehicle module, loader in `opts-game`. Verification: the shared regression test and the NG272 mass checks (design V5).
5. **Driven and braked axle loads (Part 2).** `opts-sim` drivetrain and axle modules. Verification: the friction caps change with the axle layout (a consist with only the head driven versus all units driven) in a unit test.
6. **Hitch force diagnostic (Part 2).** `opts-sim`. Verification: on a straight run `F_h = m_last · a + resistances`.
7. **Limit mapping (Part 4).** `opts-core` (parser, if a gap is found), `opts-bevy` (clamps). Verification: the two manifest-fixture tests; defaults documented.
8. **Fixed-step ground sampler (Part 3).** `opts-game` omsi_world ground code, a `FixedUpdate` system; hands heights to `opts-sim`. Verification: the sampler returns the same heights as the per-frame code for a static vehicle.
9. **β/γ and trailer pose from the fixed step (Part 3).** `opts-sim`, `opts-bevy` render interpolation, `opts-game` (per-unit block removed from `follow_ground`). Verification: the frame-rate test at 30/60/144 fps passes (design V3); the bellows tests still pass.
10. **Sweep and measurements.** `opts-core` example or test over the fleet, NG272 harness. Verification: design V6 and the NG272 criteria above.
11. **Boundary and docs (Part 5 and closure).** `docs/`: design doc interface section referenced, `articulation.md` rewritten, the M-0073 note, crate docs. Verification: link check (`scripts/check_links.py`) and review.

Steps 8–9 are the ones that touch the game schedule; 1–7 do not need M-0025.
