## 🎯 Objective

Tile streaming causes noticeable freezes. Find out exactly where the frame time goes when tiles load and unload, and implement the improvements with the best effect-to-risk ratio. Another session works on terrain and water in the same code: this milestone starts as measurement and proposal.

## 📦 Deliverables & Tasks
- [ ] **Measure first:** frame-time traces (CPU main thread, render prep, asset upload, GPU) while driving through tile boundaries on three maps; instrument the streaming pipeline with spans (tile parse, mesh build, texture decode, material/mesh creation, entity spawn, `Assets` insertion, GPU upload, despawn); record the worst frames; use the existing diagnostics or a Tracy/chrome-trace feature flag.
- [ ] **Classify the stalls:** main-thread work that must be moved (decode, parse, mesh building, entity spawn bursts), per-frame spawn budgets, texture upload spikes (large DDS/BMP decode and mip creation), eviction/despawn cost (large hierarchies), duplicate asset creation (see M-0082), lock contention, hitches from the decode cache (`descramble_cache`).
- [ ] **Candidate improvements (evaluate with numbers):** time-sliced spawning with a per-frame budget and priority by distance and view direction; worker threads for parse/mesh/decode with results applied in small batches; prefetch ahead of travel direction with hysteresis; spreading despawn over frames; sharing meshes/materials across tiles (instancing research); texture upload throttling; LOD for far tiles; the tile radius and force-load options of M-0080 as user levers.
- [ ] Write findings and the ranked proposal into `docs/src/architecture/map-streaming.md` (appendix) or a new `streaming-performance.md`; coordinate with the terrain/water owner before touching `tile*.rs`/`job.rs`.
- [ ] Implement the agreed top items behind a setting where behaviour changes; regression test with a synthetic multi-tile map measuring spawn work per frame.

## ✅ Acceptance Criteria
- The worst-frame time while crossing tile borders on the three test maps drops measurably (target: no frame above 50 ms from streaming on the reference machine; the baseline is recorded first); the report states what remains.
