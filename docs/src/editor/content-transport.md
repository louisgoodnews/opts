# Editing and Creating Transport Content

| Metadata | Value |
| :--- | :--- |
| **Status** | 📝 Specification |
| **Formats** | [`.hof`](../formats/text/vehicles/hof.md), [timetables](../formats/map/timetables.md), [lists](../formats/map/lists.md), [chrono](../formats/map/chrono.md), [`.org`](../formats/text/org.md), [ticket packs](../formats/text/ticketpacks.md), [money](../formats/text/money.md) |
| **Phase** | E5 (needs the map core, E2) |

Everything that makes a map *operate*: where buses start, where they stop, which lines run when, which vehicles and how many other road users appear, which rules signals and priorities follow. These files are text, keyword-based and partly under-specified ❓; the editor edits the documented parts through forms and tables and carries the rest through unchanged.

## 1. Depots (`.hof`)

`Vehicles/<any>/<Depot>.hof` ([`hof.md`](../formats/text/vehicles/hof.md)) defines a depot: suite directories, `[name]`, `[servicetrip]`, the `[global_strings]` of the route information system, **termini** (display strings for destinations), **bus stops** (names, announcement data) and **routes** (line number, destination boards, via text). The *Depot* editor offers:

* a table per section with the specification's fields, language columns for strings, and a **board preview** rendered by the text-texture renderer (destination matrix, roll-band, IBIS text);
* *Import stops from map*: lists the stop objects of the open map (see §2) and creates the `.hof` stop entries with matching names;
* checks: every route's termini and stops exist, strings fit the matrix width, referenced suites exist.

## 2. Bus stops and stations

A stop has three representations that must agree:

1. the **object** in a tile (a stop sign/shelter `.sco`, `[busstop]` flag; its string variables carry the stop name and line data, [tiles](../formats/map/tiles.md));
2. the **`Busstops.cfg`** entry (`name`, number, object **ID code**, dwell time, …);
3. the **`StnLinks.cfg`** links between stations (`A ==> B`, `[StnLink]`, entries) and the `[station_typ2]` references in trips (`.ttp`).

The **Stop** tool (`B`) creates all three at once: place the object on the kerb (aligned to the spline, `[path]` pedestrian lane check), enter the name, choose the dwell time; the editor allocates the ID code, appends `Busstops.cfg`, and offers to create the opposite stop. Renaming updates object string variables, `Busstops.cfg` and `.hof` stop lists together as one command; deleting a stop lists the trips that reference it.

## 3. Timetables

The chrono hierarchy (`TTData/`, `Chrono/<NNNN_Name>/TTData`) holds `.ttl` lines, `.ttp` trips, `.ttr` tracks, `Busstops.cfg`, `StnLinks.cfg`.

**Editors**

| Document | Editor | Notes |
| :--- | :--- | :--- |
| `.ttp` trip (`[trip]` destination + line, `[station_typ2]` stop IDs in route order, `[profile]` timing profiles with `[profile_man_dep_time]` / `[profile_man_arr_time]` / `[profile_otherstopping]`) | **Trip editor**: the route drawn on the map with stops; a table of stations × profiles (arrival, departure, dwell); *Drive time from distance* suggests running times from the path length and the profile's speed; profile names (`HVZ`, `Nachtbus`) | station indices in the profile lines are 1-based in the sample ❓ — written as the sample shows, verified by test files |
| `.ttl` line (`[userallowed]`, `[priority]`, `[newtour]` day type + depot + number, `[addtrip]` trip + flag + departure in minutes after midnight) | **Line diagram / Gantt**: tours as rows, trips as bars on a 24 h axis, depot runs shown, drag to retime (minutes), duplicate with offset, bulk-shift, day-type filter | consecutive trips of a tour must connect (end stop of one near the start of the next, or a depot run); the validator checks it |
| `.ttr` track (`[track_entry]`: ID code, flags, speed/length ❓) | **Track editor** for rail: pick path pieces on the map; the six fields are shown as raw until understood ❓ | trams and trains |
| `Busstops.cfg`, `StnLinks.cfg` | tables with map picking | links need the connecting road path ([`StnLink`] fields partly open ❓) |
| `Chrono.cfg`, `timeline.prt.cfg` | **Timeline**: dated variants, dates, name, ticket pack, deactivated lines; the base timetable is the first entry | `timeline.prt.cfg` is a cache of chrono paths, regenerated by the editor |

**Whole-timetable operations:** import/export CSV (line, tour, trip, stop, time), generate a **regular service** (every *n* minutes between two times from a trip template), generate return trips from an outbound trip, copy a line from another chrono, shift an entire service by a duration, renumber tours.

**Simulation preview.** *Run timetable* fast-forwards the AI scheduler (once available, [M-0049](../roadmap/phase-4/M-0049.md)) with the editor camera following a chosen trip, or draws a **time–distance diagram** (stringline chart) to see bunching and conflicts without driving.

## 4. AI traffic content

| File | Editor |
| :--- | :--- |
| `ailists.cfg` (`[aigroup_2]` vehicle groups with weights; `[aigroup_depot]` + `[aigroup_depot_typgroup_2]` fleet rows: number, plate, **repaint name**, start/end date; legacy `[ailist]`/`[aigroup]` read, written only if the file already uses it) | **Vehicle pools**: groups as lists with weight sliders and a vehicle picker with 3D thumbnails and repaint chooser (repaints are discovered from the vehicle, [repaints](content-vehicles.md#5-repaints)); **Fleet table** per depot (fleet numbers, plates from `.org`, dates) |
| `unsched_vehgroups.txt`, `unsched_trafficdens.txt` | group shares and density curves per road class over the day; chart editor; preview of the resulting counts per hour |
| `parklist_p.txt` (+ `_1`, `_2`), `humans.txt`, `drivers.txt` | weighted list editors (duplicates = weight, shown as a weight column) with thumbnails; *a faulty entry in `humans.txt`, `drivers.txt` or `parklist_p.txt` stops OMSI from loading the map*, so these editors validate that every entry exists and is the right type |
| `registrations.txt`, `.org` | number/registration pools with the `.org` semantics (pick order, weighting by repetition, consumption) |
| Alternative lists (`ailists_#low.cfg`, `_#upd`, chrono overrides, "_Alternative Ailists" folders) | a **Variants** drop-down: the editor knows which file overrides which (specification: [lists](../formats/map/lists.md)) and shows the effective list |

## 5. Traffic rules and signals

* Rules (`[rule]` in tiles) and signals are edited **on the map** ([maps §7](content-maps.md#7-traffic-rules-and-signals)); this page covers the *tables* that sit beside them.
* **Signal programs.** A junction's `[traffic_light]` records and `[phase]` timings are edited in a timeline (phases × signal heads, cycle time, offsets, minimum green); the same table feeds the AI-traffic signal model.
* **`signalroutes.cfg`** edits routes that need signal information (route → signals).
* **Priority graph.** The *Conflicts* view marks lanes whose crossing has no rule; *Suggest priorities* proposes `priority` rules from road class and arrival order for the author to accept or discard.

## 6. Calendars, time zone, money, tickets

* `Holidays*.txt`, `timezone.txt`: a year calendar and a time-zone/daylight-saving table with preview of which timetable variant applies on a date.
* `Money/<system>/…` (currency, coins): table editor; `[moneysystem]` in `global.cfg` points to it.
* Ticket packs (`.otp`): prices, ages, day-ticket behaviour, voice sets — validated against the map's money system ([assets](content-assets.md#6-fonts-sounds-ticket-packs)).

## 7. Scenarios and weather

`Situations/*.osn` (scenarios, tutorials) and `Weather/*.owt`/`envir.cfg` ([environment](../formats/text/environment.md)) are edited as forms with the in-viewport sun/sky preview; a scenario is created from the current editor state (*Save as scenario*: map, vehicle, time, weather, position).

## 8. Validation highlights for this content

Unknown stop IDs in trips; trips whose consecutive stops are not connected by drivable paths; depots without a standard-depot reference; vehicles in AI lists that are not installed; repaint names that the vehicle does not define; overlapping tours of the same vehicle; running times faster than the speed limits allow; timetable days not covered by any chrono entry; fleet numbers duplicated within a depot. The complete rule list with identifiers is in [Validation](validation.md).
