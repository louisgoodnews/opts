## 📖 Executive Summary

The code base is in far better shape than the documentation around it. All 360 tests pass, `cargo fmt` and
`cargo clippy -D warnings` are clean, the crate boundaries the previous review praised still hold for
`opts-core` and `opts-sim` (no Bevy, no I/O), and six of the ten empty stub crates were removed. Since
milestone M-0023 the game has grown from a driving demo into a program that loads real OMSI maps: streamed
tiles, terrain with a layered ground shader, splines (gradients, mirror flag, attachments), crossings and
scenery, a data-driven sky, a SQLite catalogue, structured logging, F1 bug reporting and a decoder for keyed
(scrambled) meshes.

That growth happened **outside the roadmap**. None of catalogue, logging, reporting, real-asset loading, sky,
ground shading or the descrambler has a milestone; M-0024 (tile streaming) and M-0025 (terrain) are still
"planned" although the code exists; the board was last touched on 2026-10-08. Documentation drift is the most
consistent degradation: 153 broken relative links (67 at the last review), stale crate folders for crates that
no longer exist, no link checker in CI, and a prompt library that had to be split because one file could no
longer be navigated.

Technically the biggest remaining gaps are unchanged from the last review — no OMSI script VM (🔴, the
mission-critical blocker) and no audio — plus two visible quality gaps in the new rendering path: about a third of
scrambled meshes without a plain twin are still skipped and 15 % of the accepted ones are imperfect (F-001),
and `[texttexture]` objects are parsed but never rendered, so every sign and information board is a white quad
(F-002). Size discipline has slipped: 12 files exceed the 500-line limit (`omsi_world.rs` has 1,724 lines)
and 52 functions exceed 100 lines against a hard limit of 80.

The most urgent actions are (1) bring the roadmap and board in line with what exists, (2) repair and gate the
documentation links, (3) schedule the script VM, text textures and the remaining mesh work as milestones, and
(4) split `omsi_world.rs` and the 400-line UI builders before they grow further.

## 🔬 Detailed Findings

### Dimension 1 — Code correctness

### F-001 — Scrambled meshes without a plain twin are only partly recoverable

**Severity:** 🟠
**Dimension:** Code correctness
**Location:** `crates/opts-core/src/formats/o3d/descramble.rs` (`decode_confident`), `crates/opts-core/src/formats/o3d/uvfix.rs`

**Description:** The generator behind keyed `.o3d` files is unknown. `decode_confident` recovers positions
heuristically (belief propagation + annealing, two agreeing runs) and removes texture jitter only where a planar
UV model proves it.
**Evidence:** `confident_eval` over 1,876 plain/keyed twins: 67.5 % of meshes accepted, 84.8 % of those with
≥ 98 % of positions right; exact UVs on 70.9 % of accepted vertices (49.9 % before), 1.7 % wrong. In-game log at
Dahlem U Oskar-Helene-Heim: 118 scrambled meshes, 94 accepted, 24 still skipped.
**Impact:** Missing signs and junction pieces on some maps; wrong vertices on a minority of decoded meshes;
mis-textured vertices on ~29 % of decoded vertices. Normals are recomputed.
**Suggested action:** Keep researching the state chain (`q = n·s mod 8000`, see `o3d.md` Addendum 5); until then
track coverage as a metric and show decoded/skipped counts in the F10 overlay.

### F-002 — `[texttexture]` objects render as white quads

**Severity:** 🟠
**Dimension:** Code correctness
**Location:** `crates/opts-core/src/formats/scenery/sco.rs` (`ScoTextTexture`), consumers in `crates/opts-bevy/src`, `crates/opts-game/src` (none)
**Description:** `[texttexture]`/`[texttexture_enh]` are parsed but no code renders text into the object texture.
**Evidence:** `grep -rn "texttexture\|TextTexture" crates/opts-bevy/src crates/opts-game/src` finds nothing;
user screenshots of X10 Berlin show white boards with only a faint "B".
**Impact:** Every stop sign, street sign and destination board is unreadable; the runtime texture references
(`\S:n`, `Textfeld_*`) are silently ignored.
**Suggested action:** Add a text-texture renderer (font rasterisation into an `Image` per object instance, string
variables from the tile's `string_vars`).

### F-003 — Descrambling blocks the render thread

**Severity:** 🟡
**Dimension:** Code correctness
**Location:** `crates/opts-bevy/src/model.rs:319` (`decode_confident` call inside `load_o3d`), `crates/opts-game/src/in_game/omsi_world.rs:692` (`load_next_tile`)
**Description:** Decoding happens synchronously while a tile is built.
**Evidence:** Dahlem log: 118 decode calls, slowest 1,625 ms, several above 300 ms; the on-disk cache only helps from the second run.
**Impact:** Frame stalls of seconds when streaming a tile with many uncached keyed meshes.
**Suggested action:** Move decoding to `AsyncComputeTaskPool` (the plan in M-0024) or pre-warm the cache in the loading stage.

### F-004 — Spline attachment repeater semantics are a guess

**Severity:** 🟡
**Dimension:** Code correctness
**Location:** `crates/opts-game/src/in_game/attachments.rs` (`expand_attachments`), `docs/src/formats/map/tiles.md` (Spline attachments)
**Description:** `[splineAttachement_repeater]` is read as `count` instances spaced `span/count` along the chain; single attachments are validated, repeaters only by plausibility.
**Evidence:** 83 % of repeater distances fall inside their carrier spline; the `span`/`count` meaning is documented as unproven.
**Impact:** Street lights, trees and bays along roads may be mis-spaced or mis-placed.
**Suggested action:** Verify against an OMSI screenshot of a known road with repeaters before relying on it.

### F-006 — Remaining panicking calls in library code

### F-008 — Sky is approximate and the fallback keeps hard-coded lighting

**Severity:** 🟡

**Location:** `crates/opts-game/src/in_game/sky.rs:19` (`LATITUDE_DEG`), `crates/opts-game/src/in_game/world.rs:10` (`spawn_atmosphere_and_lighting`)
