# Bug: Splines invisible from above on Waldhofen ("spline winding")

| | |
| :--- | :--- |
| ID | f17228d9-3bc0-4830-8f25-3bc9465f63d2 |
| Date | 2026-10-10 16:44:31 |
| Map / place | Waldhofen, entry "Schloss Salthammer 595", tile (18, -6) |
| Status | Fixed |
| Owning crate | `opts-bevy` (`terrain.rs`), called from `opts-game` (`omsi_world/tile.rs`) |

## Symptom

Road splines were not visible from above ground but showed from below. The report suspected inverted
face winding or a per-spline flag in the tile file.

## Reproduction

1. `OPTS_DEV_ENTRY="Salthammer 595" cargo run --release -p opts-game -- --map-path ".../maps/Waldhofen" --autostart --cli-port 44201`
2. `opts-cli camera.set_mode free`, then `opts-cli camera.teleport 5425.2 -1730.9 -7 --yaw 0 --pitch -45`
   and `opts-cli screenshot --path ~/.local/share/opts/reports/x.png`.
3. Before the fix only the lane markings poke through grass-green terrain; teleporting below the road
   (z −15, pitch +89) shows the full asphalt ribbon.

## Root cause (with evidence)

*Not* winding, culling or a flag:

- Spline materials are already `double_sided` with `cull_mode: None`, so winding cannot hide a face.
- `crates/opts-bevy/tests/spline_winding.rs` proves the ribbon winding is right for 50 layouts
  (headings, left/right arcs, slopes, mirrored): top faces have normal +Y, the reversed profile yields −Y.
- All 7,210 `[spline]` blocks of Waldhofen carry flag `0`; there is no per-spline flag.
- The terrain grid in the tile's `.terrain` file lies **above** the road surface. For
  `str_2spur_8m_DDR_Spandauer_Str_1990.sli` (surface = z + 0.10) the terrain at the spline origin is
  z + 0.25 (`opts-core/examples/winding_probe.rs`: `dz = -0.250`), i.e. 0.15 m over the carriageway;
  the 5 m grid picks up the 0.25 m curb strip of the height profile. The Bevy hardware `depth_bias`
  (4 units, ≈ 1e-6 in depth) cannot bridge that, so the opaque terrain wins the depth test from above and
  loses it from below, where its back face is culled.

## Fix

`opts-bevy/src/terrain.rs`: `road_footprint` samples the centreline of every spline whose profile has a
`[heightprofile]` and records half-width and the lowest profile height; `carve_terrain_under_roads`
caps every terrain vertex within `half_width + ½ cell` of such a centreline at the road surface minus
3 cm (clearance). Everything else stays as authored. `opts-game/.../tile.rs` carves a copy of the
tile's terrain before `build_terrain_mesh`; object placement still samples the authored terrain.
Culling stays on for terrain, nothing is flipped.

## Regression test

`cargo test -p opts-bevy --test spline_winding` (synthetic, no OMSI install): top faces face +Y, undersides
face −Y, curb risers face outward, vertex normals point up, terrain 0.25 m above a road is carved below
it, terrain away from it and splines without height profile are untouched.

## Verification

- Waldhofen (18, −6): road and curb visible from above after the fix (screenshot `w_fix_above.png`).
- Grundorf: road and bus render correctly, 22 splines, 0 failures (`g_fix.png`).
- Regression checklist (vehicles, scenery, terrain, shadows, materials): bus, trees and buildings
  unchanged in both scenes; terrain still shadowed and textured; spline materials unchanged;
  `cargo clippy --workspace --all-targets -- -D warnings` clean; `cargo test --workspace` all green.

## Spec updates

`sli.md` ([heightprofile]) and `tiles.md` note the terrain/road height mismatch; `coordinates.md` is unchanged.
