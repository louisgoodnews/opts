## 📖 Purpose

This file is the **single source of truth for active work** on the
OPTS project. It is not a roadmap — the roadmap lives in
[`ROADMAP.md`](../../ROADMAP.md) and in the per-phase milestone files
under [`docs/src/roadmap/`](../../docs/src/roadmap/). It is not a
backlog of ideas — those go into GitHub Issues.

This board answers one question: **"What is being worked on right
now, and what's next?"**

It is maintained by the dev agent under the workflow defined in
[`dev/prompts/README.md`](prompts/README.md):

| Prompt | Board Action |
| :--- | :--- |
| **P-004** — Board Update | Populates new work items from an approved plan |
| **P-005** — Implementation | Moves items between In Progress / Review / Done |
| **P-006** — Roadmap Update | Closes out completed items and archives |

Do not edit this file manually without running the corresponding
prompt. Drift between the board and the milestone files is a bug.

## ✅ Definitions

### Definition of Ready

A work item may enter the **Ready** column only when:

1. It has a milestone reference (`M-NNNN`).
2. Its acceptance criteria are testable and unambiguous.
3. All of its dependencies are met (specs exist, crates are
   available, related items are Done).
4. It fits in a single agent session (roughly one focused hour).
5. It has been reviewed by an adversarial pass (see P-003).

### Definition of Done

A work item may enter the **Done** column only when:

1. All acceptance criteria pass.
2. Tests are written and passing (`cargo test`).
3. `cargo clippy --all-targets -- -D warnings` passes.
4. Every public item has rustdoc (`///`).
5. Every new module has `//!` module documentation.
6. The relevant `docs/crates/<crate>.md` entry is updated.
7. The milestone file's checklist is updated.
8. Commit follows the `<type>(<scope>): <desc> (M-NNNN)` convention.
9. If the work touched a format spec, the spec is updated with any
   new facts and its Open Questions table reflects resolved items.

## 🧭 How the Board Gets Maintained

The board is not a diary. It is a **queue with state**. To keep it
that way, three rules apply:

### Rule 1 — P-004 Populates, Nothing Else

New work items only enter the board via P-004, after a milestone plan
has been approved by P-003. Ad-hoc additions are forbidden. If you
want to add something to the board, add it to a milestone plan first.

### Rule 2 — P-005 Moves Items

The agent moves items between columns only during P-005 execution:

| Transition | Trigger |
| :--- | :--- |
| Ready → In Progress | First action on the item |
| In Progress → Review | Coding complete, tests pass, awaiting P-003-style review |
| Review → Done | Review passes, milestone checklist updated |
| In Progress → Blocked | A dependency is discovered mid-work |
| Blocked → Ready | Dependency resolved |

### Rule 3 — P-006 Archives

On milestone closeout, P-006 moves all Done items into the "Recently
Done" section, dated and grouped by milestone. Items older than two
cycles are dropped entirely — they're recoverable from git history
and the milestone file.

The agent should check these during P-001 audits:

| Metric | Target | Red Flag |
| :--- | :--- | :--- |
